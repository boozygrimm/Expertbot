# Луна-парк Бендера — лаборатория открытий: процесс и планы

## Что это

Единый Mini App «Луна-парк Бендера» строится на базе существующего Telegram-бота. Первый видимый этап — автономный визуальный прототип **Лаборатории открытий**: котёл, в котором игрок открывает рецепты, собирает коллекцию элементов, смотрит историю и альбом открытий.

Сейчас это полностью автономная HTML-страница: прогресс не сохраняется, сетевого доступа нет, бота не задействовано. Это прототип дизайна и механики, не production.

## Текущий результат

- Файл: `lunapark-discovery.html` (сборка из `miniapp_preview/`).
- Публикация: `https://htmlpreview.github.io/?https://github.com/boozygrimm/Expertbot/blob/<commit>/lunapark-discovery.html`
- Бранч: `arena/771875a3-expertbot`
- Исходники: `miniapp_preview/discovery.html`, `discovery.css`, `discovery.js`, `build_discovery.py`.
- Сборка: `.venv/bin/python -m miniapp_preview.build_discovery` из корня репозитория.

## Процесс работы

### 1. Базовая механика лаборатории

- Четыре стартовые стихии: вода, огонь, земля, воздух.
- Лаборатория только **открывает рецепты**: не тратит ресурсы, не создаёт предмет на складе.
- Открытые элементы доступны для смешивания в любом количестве, без требования наличия на складе.
- Порядок ингредиентов не важен, одинаковые элементы допустимы.
- Смешивание открывает новый элемент или показывает, что реакции нет.

### 2. Компоновка котла

- Три круглых окошка: ингредиент 1 — центральное ситуационное — ингредиент 2.
- Кнопки «История» и «Рецепты» расположены выше котла по углам.
- Освободившееся место использовано для дополнительного ряда элементов.
- Поддержка нажатия и перетаскивания.

### 3. Ситуатное центральное окошко

- Пустое в начале.
- При одном ингредиенте: пусто или подсказка «Добавь второй».
- При двух: кнопка «Смешать».
- Для уже проверенной пары: «Было, это …».
- После неудачи: кнопка «Очистить», но ингредиенты остаются в котле, и можно заменить элемент, не очищая.
- После успеха: шарик нового элемента.
- Подписи присутствуют.

### 4. Полёт результата и начало следующего

- Плавный полёт полученного шарика из котла к коллекции.
- После успешного смешивания следующий выбор начинается с первого слота.
- Явная замена любого слота остаётся возможной.

### 5. История и альбом

- История попыток с отметками проверенных пар.
- Страница истории по **10 записей** (`HISTORY_SIZE = 10`).
- Альбом открытий: результат и найденные способы получения.
- Карточка элемента с парой и кнопкой «В котёл».
- Повторная комбинация не дублируется, новый способ получения известного элемента добавляет новый рецепт.
- Катетегории, поиск, избранное, недавние, сортировка, скрыть тупиковые.
- Компактные страницы вместо горизонтальных лент.

### 6. Символы элементов

- Настоящие эмодзи из словаря `ELEMENTS` (`handlers/alc_recipes.py`).
- В лаборатории у значка нет числа: символ внутри кружка, название вдоль нижней границы.
- Полное имя доступно при выборе.

### 7. Изогнутая подпись шарика

- Подпись идёт по дуге вдоль нижней границы шарика.
- Поддержка длинных названий: дуга плоская, буквы центрованы, шрифт уменьшается по длине.
- Шрифт: Segoe UI / system-ui, вес 500, мягкая тень, без жёсткой обводки.
- Проверка геометрии: буквы внутри окружности, перекрытий нет.

### 8. Стихийная составляющая и цвет

- Для каждого элемента считается вектор стихий: вода / огонь / земля / воздух.
- Базовые стихии берутся напрямую, остальные — по смыслу и рецепту (рецепт даёт намек).
- По вектору вычисляется **цвет шарика**: вода — синий, огонь — красный, земля — коричневый, воздух — светлый.
- Смешанные элементы получают смешанный цвет.

### 9. Агрегатное состояние и текстура

- Для каждого элемента считается физическое агрегатное состояние: огонь, газ, жидкость, песок, твёрдое, органика.
- По состоянию выбирается **текстурная заливка** с анимацией:
  - огонь — вихрь + мерцание;
  - газ — вихрь + дрейф тумана;
  - жидкость — вихрь + волнение;
  - песок — движущиеся грани;
  - твёрдое — вихрь + мерцание структуры;
  - органика — пульсация.
- Добавлено **пульсирующее свечение** у шарика по состоянию, чтобы анимация была видна и в коллекции, не только в котле.
- Доступен переключатель эффекта он/офф (кнопка ✦ вверху справа).

### 10. Звук

- Опциональные звуки успеха/неудачи.
- Переключатель звука в правом верхнем углу.

## Техническая архитектура

- Данные берутся из `handlers/alc_recipes.py`: `ELEMENTS` (370 элементов), `RECIPES` (363 рецепта), `is_battle_unit`.
- Сборщик `miniapp_preview/build_discovery.py` упаковывает данные, CSS и JS в один `lunapark-discovery.html`.
- Фон котла — `miniapp_preview/assets/discovery_cauldron.jpg`, встроен как base64.
- Нет network-запросов, нет Telegram, нет БД. Всё локально в браузере.

## Тесты

- `miniapp_preview/discovery.test.cjs` — jsdom, 5 тестов: ситуационное окно, фильтры, выбор слотов и очистка, история по 10 записей и эмодзи, защита реакции.
- `miniapp_preview/discovery_viewport.test.cjs` — Chromium, 2 теста: вписывание в экран, перетаскивание, полёт элемента.
- Запуск:
  - `node --test miniapp_preview/discovery.test.cjs`
  - `LD_LIBRARY_PATH=/tmp/al2023/lib node --test miniapp_preview/discovery_viewport.test.cjs`

## Текущие ограничения

- Прототип не сохраняет прогресс.
- Нет интеграции с ботом, профилем, подсказками и фоновой логикой.
- Подсказки через чат-бота существуют, но сейчас не подключены.
- Найм и крафт в постройках — отдельный этап, сейчас не решаются правила и не меняются боевые рецепты.
- Очистка базы и restart прогресса — только после согласования и с резервной копией.

## Дальнейшие планы

1. **Интеграция с backend**
   - Подключить лабораторию к существующей Python-логике: проверка рецептов, открытие элементов, история, альбом.
   - Сохранение прогресса игрока: открытые элементы, найденные пары, история, избранное, недавние.
   - Защита данных и совместимость с существующей системой подсказок.

2. **Продолжение UI**
   - Сделать основной экран парка с видимыми постройками и павильонами.
   - Лаборатория — отдельная сцена с возвратом в парк.
   - Ретрофутуристический стиль в духе «Футурамы»: хаос и магия.
   - Анимации для полёта, реакции, открытия элементов.

3. **Расширение механик**
   - Альбом открытий: показать все найденные способы получения элемента.
   - Катетегории, поиск, избранное, недавние, сортировка — в полном объёме.
   - Опциональные подсказки, подсказки через бот.
   - Найм и крафт в постройках — отдельно, после согласования.

4. **Производственная готовность**
   - Telegram Web App integration: безопасная проверка `initData`, профиль бота.
   - Хранение прогресса в БД (MongoDB/existing infrastructure).
   - Фоновые процессы и scheduler.
   - Rate limiting, мониторинг, резервное копирование.

5. **Очистка данных**
   - Выполнить очистку базы и reset прогресса только после отдельного согласования и резервной копии.

# Луна-парк Бендера — интерактивная песочница

## Автономный просмотр без установки

Файл `../lunapark-offline.html` можно скачать целиком и открыть в браузере без
запуска сервера. В нём встроены изображения и интерфейс, а крафт и производство
имитируются JavaScript-кодом прямо в браузере. В лаборатории ингредиенты можно
перетащить в котёл или выбрать нажатием; разделы открываются нижними кнопками,
основные экраны помещаются в видимую область. Длинные ряды элементов и сцену
базы можно листать горизонтально. На сцене базы видны уровни построек, а на
сцене походов — условные анимированные отряды по статусам.
Иллюстрация базы не меняется в зависимости от уровня; изображение отрядов не
обозначает их реальное местоположение или состав. Это **отдельная упрощённая
демоверсия**, не Python-сервер и не игра с настоящим профилем; изменения исчезнут
при перезагрузке и не разделяются между посетителями. Он не обращается к сети.

После изменения исходников пересобрать файл из корня репозитория:

```sh
python -m miniapp_preview.build_offline
node --test miniapp_preview/offline.test.cjs
```

Этот тест использует jsdom. Дополнительный `viewport.test.cjs` запускает
Chromium, проверяет размеры от 320×480, альбомную ориентацию, доступность кнопок,
горизонтальный свайп и перетаскивание с имитацией касания. Его зависимости
`puppeteer-core` и `@sparticuz/chromium` устанавливаются отдельно и не входят
в сборку приложения; системе также могут понадобиться библиотеки NSS/NSPR.
Это не проверка на настоящем телефоне или Telegram WebView. Для генерации нужны
Python-зависимости экспериментальной песочницы и `jsdom` для основного теста.

Парк и лаборатория соединены с **изолированным тестовым сервером**. На сервере
живёт один общий искусственный профиль с инвентарём, рецептами, бойцами,
экспедициями, производством и постройками. Котёл позволяет попробовать крафт по
существующему справочнику рецептов. В производстве можно разобрать линию,
запустить станцию с духом или без него и вручную прогнать один тестовый час.
Ресурсы сразу поступают на склад; виртуальное время не идёт автоматически. Это
**не** реальный Telegram-вход и не база
игроков: сервер использует публичный фальшивый токен и хранит состояние в памяти.
Все посетители стенда видят один общий профиль; при рестарте сервера он сбрасывается.

Запуск из корня репозитория после установки `aiohttp`:

```sh
python -m miniapp_backend.sandbox --port 8001
```

Откройте `http://localhost:8001`. Сервер по умолчанию слушает только localhost;
для удалённого предпросмотра нужен `--host 0.0.0.0`. Он раздаёт только явный
список файлов и только вымышленные данные, без токенов окружения или MongoDB.
Не запускать этот тестовый сервер как production и не переносить его публичные
фальшивые маршруты или ключ в приложение с настоящими данными.

Для простого статического просмотра без сервера приложения всё ещё можно
запустить `python -m http.server 8000 --directory miniapp_preview`: в таком
режиме карточки показывают примеры, а крафт не включён.

## Проверки

```sh
python -m pip install aiohttp motor mongomock-motor aiogram python-dotenv Pillow apscheduler==3.10.4
python -m unittest -v tests.test_miniapp_backend tests.test_miniapp_sessions tests.test_lunapark_sandbox tests.test_miniapp_crafting tests.test_miniapp_isolated_store tests.test_miniapp_production tests.test_sandbox_production
npm ci --prefix miniapp_preview
MINIAPP_PYTHON="$(command -v python)" npm test --prefix miniapp_preview
```

Node-тесты используют jsdom и локальный тестовый HTTP-сервер; это не проверка
настоящего Telegram WebView. Тестируются, в частности, загрузка профиля, отказ
API без подмены примерами, крафт и безопасная вставка текста. Тесты не подключаются
к внешним сервисам.

Картинки `assets/` — уменьшенные копии согласованных концептов из `design/`;
из концепта лаборатории обрезаны выдуманные показатели. Отдельный read-only Telegram-стенд с SDK подготовлен в `miniapp_backend/telegram_stand.py`,
но ещё не подключался к настоящим Telegram или MongoDB; подробности и условия
запуска — в `miniapp_backend/README.md`. Подключение рабочего профиля и игровые
записи появятся отдельно после согласования и тестов безопасности. Пока крафт и
производство реализованы только внутри песочницы: её блокировка и журнал запросов в памяти не решают гонки в MongoDB
и не предназначены для реальной игры.

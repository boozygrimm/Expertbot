# Discovery laboratory design demo

`python -m miniapp_preview.build_discovery` builds `lunapark-discovery.html` from the adjacent `discovery.*` sources, an illustrated cauldron background and the existing Python recipe definitions. This is an isolated, network-free visual/interaction demo; it does not affect the bot, sandbox API or database. It intentionally resets on page reload. It is not a secure game implementation: all recipe data is embedded in the HTML and can be inspected by a user.

It starts with four elements; successful unique pairs go to the album, attempts go to a short local in-memory history. Failed and successful combinations do not consume resources. Recipe pairs are unordered. Unit and special-pack/scroll recipes are excluded pending future design. Existing recipe keys that collide in Python have already overwritten one another before the build; the demo does not repair them. Three round controls sit on the cauldron: two ingredient slots and a larger situational central window. It is empty initially; with one ingredient it asks for a second; with two untried elements it becomes the actionable **Смешать** control. The mix shows an animated cauldron reaction, and then the central window shows a successful element or, after a failed pair, the actionable **Очистить** choice. A failed pair is not consumed automatically: the slots stay until the player clears them or replaces either ingredient. For an already tried pair the central window shows the previous result, or that no reaction exists and offers clearing. On success the element flies to the collection (with reduced-motion support). After a successful mix the next two choices replace the first and second slots unless a slot is explicitly selected. The collection shows up to twelve elements per page, while the laboratory journal shows ten attempts per page. Element symbols are lightweight vector emblems selected from the element's semantic category; unmatched elements get a deterministic geometric emblem instead of a temporary initial. Curved orb labels are placed along the arc using estimated glyph widths, so longer names do not crowd adjacent letters. Sound is opt-in. Dead-end indication reflects only the recipes included in this prototype, not all game systems. The existing chat hint system is not connected.

Tests: `node --test miniapp_preview/discovery.test.cjs` and, with the optional Chromium dependencies described in the main README, `LD_LIBRARY_PATH=/tmp/al2023/lib node --test miniapp_preview/discovery_viewport.test.cjs`.

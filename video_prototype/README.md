# Ручной прототип видеокружков

Это отдельный CLI для проверки цепочки на InstaBox, **не интеграция в бота** и не
публичный сервер. LLM, БД, очередь, кэш и панель не подключены. Анимация намеренно
заменяема: сейчас это проверенный PNGTuber с двумя положениями рта, реагирующими
на громкость, и двумя фиксированными морганиями. Это не фонемный lipsync.

## Что нужно на InstaBox

- `ffmpeg` с `libx264` и AAC в `PATH`.
- Python-окружение `/data/video-prototype/.venv` с Pillow.
- Для генерации голоса: `/data/qwen-prototype/.venv` с `qwen-tts`, PyTorch и
  `soundfile`; модель `Qwen/Qwen3-TTS-12Hz-0.6B-Base` в
  `HF_HOME=/data/qwen-prototype/hf`.
- Исходная запись для клона `/data/qwen-prototype/reference.wav` и точная
  расшифровка этой записи. В коде задана расшифровка текущего эксперимента;
  при смене образца надо передать `--reference` и `--reference-text`.
- `/data/video-prototype/preview/closed.png`, `open.png`, `blink.png` —
  согласованные одинаково кадрированные квадратные картинки. Координаты масок
  привязаны к ним: другая композиция потребует обновить маски в `render.py`.
- Для отправки — тот же бот, администратор канала-склада; доступ к целевому чату.
  Токен запрашивается в терминале скрытым вводом или берётся из `BOT_TOKEN`.
  Никуда в чат его отправлять не нужно. Токен даёт доступ ко всему боту.

## Проверка без TTS и без Telegram

Из каталога, в котором находится `video_prototype/`:

```bash
python3 video_prototype/pipeline.py --audio /data/qwen-prototype/voices/reference_test.wav --no-send
```

Выведется путь к `video.mp4` в новой папке `/data/video-prototype/clips/clip-…`.
Для просмотра её можно временно раздать через знакомый HTTP-сервер. Публичная
раздача открывает файлы в выбранном каталоге. Параметры `--frames-dir`,
`--output-dir`, `--render-python` меняют расположения.

## Весь ручной цикл

```bash
python3 video_prototype/pipeline.py --text 'Ну, чего уставился? Я Бендер. Давай, удиви меня!' --channel-id -1001234567890 --chat-id -1002345678901
```

В примере указаны условные ID; подставьте реальные. После рендера скрипт запросит токен, загрузит MP4 в канал, сохранит Telegram
`file_id` в `result.json` и отправит его в тестовый чат. Если не указывать
`--chat-id`, отправка будет только в канал. Для пробы без Telegram можно
заменить оба ID на `--no-send`. Длинный текст может быть обрезан моделью или
дать видео длительностью 60 секунд и больше; такой ролик здесь отклоняется.
Качество Qwen и длительность для новой фразы необходимо проверять.

Для ручного теста ответа можно дополнительно указать `--reply-to-message-id ID`;
это ID сообщения **в выбранном чате**. Для темы форума также поддерживается
`--message-thread-id ID`. По умолчанию ручной запуск не отвечает на сообщение.
`--chat-id` выбирается при каждом запуске, в коде нет фиксированного чата.

Будущая интеграция в бота должна брать `message.chat.id` и `message.message_id`
из каждого конкретного запроса, а для тем — соответствующий `message_thread_id`.
Если запрос сделан ответом, контекст исходного сообщения следует передавать по
аналогии с «Экс мнение»: `get_reply_source_text` берёт текст или подпись.
Сам кружок отвечает на сообщение с запросом, как `message.reply` в существующем
обработчике. Это пока только требование, не реализованное подключение к боту.

При сбое повторной отправки `result.json` сохраняется после загрузки в канал,
чтобы не потерять `file_id`. Папки с результатами на `/data` накапливаются,
автоматического удаления пока нет. Текст, запись голоса и медиа могут быть
чувствительными: этот эксперимент не является безопасным продакшен-сервисом.
При публичном использовании чужого голоса или образа следует проверить права.

Тесты без модели и Telegram:

```bash
python3 -m unittest tests.test_video_prototype -v
```

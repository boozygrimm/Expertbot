## 2. Инфраструктурные факты (Render + MongoDB)

- Бот (`aiogram` + `APScheduler`) и встроенный `aiohttp`-сервер (`start_healthcheck_server` в `app_setup.py`) крутятся на **Render**.
- **Render живёт на внешнем пинге без засыпаний** → холодный старт и warm-up-запросы не требуются.
- В репозитории уже подключены `aiohttp` (`app_setup.py`) и асинхронный `motor` (`database.py`, БД `beleyakov_db`). Новых зависимостей в `requirements.txt` для бэкенда RAID не нужно.
- **Условие старта Этапа 1:** сначала владелец подключает MongoDB в Render. Переходить к реализации серверной части — после подтверждения от владельца.

## 3. Этап 1 — Релиз на Render: профиль, синхронизация и Общий лидерборд

Главная задача этапа — подключить стабильный общий лидерборд и облачную синхронизацию прогресса без регистрации и без влияния на стабильность основного бота.

### 3.1. Бэкенд (`app_setup.py` + новый модуль, например `raid_api.py`, + `database.py`)
1. **Авторизация без учёток:** проверка `Telegram.WebApp.initData` (заголовок `Authorization: tma <initData>`, HMAC-SHA256 через `BOT_TOKEN`, проверка `auth_date`). `tg_id`, `username` и `first_name` берутся строго из проверенного `initData`.
2. **CORS и конфигурация:**
   - CORS middleware в `aiohttp` с разрешением `Origin: https://boozygrimm.github.io` (+ `OPTIONS` preflight).
   - URL бэкенда задаётся через переменную окружения `RAID_API_URL` (передаётся в ссылку `/raid_test` через `?api=...` или дефолт).
3. **Защита стабильности бота:**
   - Только асинхронные запросы через `motor`, никаких блокирующих операций в event loop.
   - `client_max_size=64 * 1024` (64 КБ), простой rate-limit по `tg_id` (например, 1 отправка забега раз в 3–5 сек), полная изоляция исключений (`try/except` → JSON `500`), чтобы сбой API никогда не ронял Telegram-бота.
4. **Схема MongoDB и индексы (создавать при старте рядом с `ensure_message_retention()`):**
   - `raid_profiles` (`_id: tg_id`):
     - `display_name`, `username`, `updated_at`
     - `classes` (открытые мехи и их уровни), `trophy_remaining`, `achievements`, `ascension` (задел под Этап 2)
     - *Активный незавершённый забег (`activeRun`) остаётся локально в `localStorage`, чтобы не дёргать сервер на каждом ходе.*
   - `raid_runs`:
     - `tg_id`, `history_id` (уникальный индекс `(tg_id, history_id)` — идемпотентность и защита от дублей при ретраях)
     - `score`, `turns`, `level`, `class_id`, `difficulty`, `region`, `ascension`, `build`, `duration_sec`, `created_at`
     - Индекс `(difficulty, score: -1, created_at: 1)` для быстрого топ-50 и расчёта позиции игрока `#N`.
     - Базовая серверная санитизация адекватности цифр (базовый античит).
5. **Минимальный набор из 4 эндпоинтов:**
   - `GET /api/raid/profile` — получить облачный профиль игрока.
   - `POST /api/raid/profile/sync` — мягко синхронизировать прогресс (объединение max уровней/открытых мехов и достижений между устройствами).
   - `POST /api/raid/runs` — сохранить завершённый забег (идемпотентно по `history_id`) и вернуть обновлённую позицию в топе.
   - `GET /api/raid/leaderboard?difficulty=1&limit=50` — общий топ по сложности + строка «Твоё место: #N».

### 3.2. Клиент (`miniapp_preview/raid_magitech.*`) и бот
- **Офлайн-надёжность:** неблокирующие `fetch()` с таймаутом (`AbortController` ~8–10 сек). Если у игрока моргнул мобильный интернет в конце боя — результат сохраняется в локальную очередь в `localStorage` и автоматически доотправляется при следующем заходе (или кнопкой «Повторить»). При недоступном API игра продолжает полностью работать локально.
- **Вкладка «Общий топ»** внутри окна «Рекорды» (фильтры Лёгкий / Нормальный / Сложный, подсветка своей строки и места).
- **В боте:** кнопка/команда посмотреть общий топ RAID прямо в Telegram.

## 4. Этап 2 — Развитие и реиграбельность (после релиза на Render)

Владелец отобрал **4 направления** из списка идей; каждое требует короткого согласования деталей и баланса перед реализацией.

### 4.1. Реликвии / Артефакты после боссов *(приоритетный геймплейный буст)*
- Победа над каждым боссом даёт выбор **1 из 3 Реликвий на текущий забег**, меняющих правила и создающих синергии билдов.
- Примеры механик (для доработки): «Магнит цепей» (длинные цепи монет бьют врага), «Кровавый точильный камень» (оверхил → бонус к урону), «Аварийный щит» (автозаморозка при низком HP), «Алхимический перегон» (кислотные зелья бьют врагов), «Стеклянная пушка» (урон ×1.5, меньше брони) и др.
- **Что уточнить перед кодом:** стартовый пул (15–20 реликвий), отображение активных реликвий в компактном HUD/сводке, совместимость с сохранениями.

### 4.2. Уровни угрозы / Восхождение (Ascension 1–10)
- После достижения вехи (например, победа над N-м боссом / 100-й ход) для меха открывается **Уровень угрозы +1** (до 10), пошагово усложняющий забег (чаще боссы, доп. свойства особых врагов, дороже магазин и т. д.).
- Награды: визуальная медаль/рамка на карточке меха в гараже + множитель очков в общем лидерборде + синхронизация через `raid_profiles`.
- **Что уточнить перед кодом:** условие открытия следующего уровня, точная таблица модификаторов 1–10 и формула множителя очков.

### 4.3. Интерактивные события «риск / награда» между боссами
- Раз в 15–20 ходов — короткая карточка выбора (2–3 кнопки, на 5 секунд):
  - *Заброшенная кузница* (усилить меч за счёт HP / разобрать на золото / уйти),
  - *Странствующий алхимик* (случайный эликсир с риском / покупка лечения),
  - *Алтарь крови* (обмен ресурса или слота на сильный постоянный бафф) и т. д.
- **Что уточнить перед кодом:** частота появления, пул событий (10–15 штук), запрет на «мгновенную смерть» от неудачного события.

### 4.4. Социальные фишки под Telegram
- **Вызов другу / Дуэль по сиду** (коллекция `raid_challenges` в MongoDB): кнопка «Бросить вызов» на экране итогов генерирует deep-link с тем же `seed`, мехом и сложностью — друг играет то же поле и пытается побить рекорд.
- **Карточка итогов для репоста в чат:** компактное оформление забега (мех, ход, счёт, реликвии, уровень угрозы) + кнопка «Побить рекорд».
- **Опционально — «Тень рекордсмена»:** компактный ориентир в дуэли/забеге, сколько очков было у соперника к текущему ходу.
- **Что уточнить перед кодом:** формат deep-link в боте (`startapp` / `/raid_test`), нужен ли отдельный режим «Забег дня» (Daily Seed) вместе с дуэлями.

## 5. Правила работы с RAID (инварианты)

- Все правки ведутся в `miniapp_preview/raid_magitech.{html,css,js}` с обязательной пересборкой `lunapark-raid-magitech.html` через `python3 miniapp_preview/build_raid_magitech.py`.
- Перед коммитом/PR обязательно прогонять:
  1. `python3 miniapp_preview/check_build.py`
  2. `python3 -m unittest tests/test_raid_duplication.py`
  3. релевантные тесты `miniapp_preview/integration.test.cjs` и `miniapp_preview/test.mjs`
- Обычный процесс: коммит → PR в `main` → мерж только после явного одобрения владельца.

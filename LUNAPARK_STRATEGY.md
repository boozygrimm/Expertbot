# Стратегия Mini App «Луна-парк» — вариант 3: замена текстовой алхимии

**Дата:** 2026-11-21. **Статус:** стратегия, к исполнению не принята. Кода в этой
правке нет.

Вариант 3 учитывает решение владельца, которое меняет масштаб проекта: **текстовая
алхимия в боте заменяется мини-аппом**, а алхимия становится одним из аттракционов
Луна-парка Бендера. Ниже — что из этого следует по фактам кода и что осталось
открытым.

## 1. Решения владельца

| Вопрос | Ответ | Следствие |
|---|---|---|
| Судьба прогресса | обнуляем, старая база остаётся архивом | перетаскивать старые склады/уровни не нужно |
| Объём перехода | постепенно: сначала лаборатория, потом остальное | старая игра гаснет по частям, а не одним днём |
| Команды в боте | пока не решено, гасим на втором этапе | на первом этапе старые команды работают |
| Кто пишет в инвентарь | только Mini App | старых писателей не нужно чинить — их нужно выводить из эксплуатации |
| Активность в чате | только по кнопке «Поделиться в чат» | автоматические публикации событий в чат отключаются |
| Старый код и тесты | 155 тестов и 14,5 тыс. строк сохраняются как описание правил | расчёты и рецепты берём оттуда как эталон |

## 2. Главное следствие: риск резко падает

В варианте 2 главной опасностью были гонки записи: 27 мест `$set inventory` в 10
файлах, `alc_lab.py:411–437`, `alc_tasks.py:188–191`, тик `alc_expeditions`
каждую минуту. **Если писать в инвентарь будет только Mini App, а бот перестанет
писать, все эти места можно не чинить, а выключить.**

Но это работает только при одном условии, и его надо соблюдать буквально: у
каждого поля ровно один писатель. На первом этапе бот ещё работает, поэтому
нужно разделение по полям:

| Данные | Кто пишет на первом этапе |
|---|---|
| `inventory`, `discovered` лаборатории | Mini App (новая коллекция или новые поля) |
| старое `alchemy_players.inventory` | бот, как раньше |
| всё остальное (бойцы, база, походы) | бот, как раньше |

Если два пути пишут в одно и то же поле, гонки возвращаются. Поэтому новая
лаборатория **не должна** использовать `alchemy_players.inventory` на первом
этапе — иначе придётся делать слой записи сразу.

## 3. Что это значит для первого этапа

Минимальный первый этап, который не пересекается со старым кодом:

1. Мини-апп пишет свой прогресс лаборатории в **отдельное место** (новая
   коллекция, привязанная к проверенному Telegram user ID).
2. Ни одна строка `handlers/alc_*.py` не меняется — старая игра работает как
   раньше, со своей базой.
3. Когда лаборатория в мини-аппе догонит по объёму нужное владельцу — старые
   команды лаборатории выключаются, а её поля становятся архивом.
4. Только после этого имеет смысл обсуждать «второй аттракцион» — и каждый
   следующий переносится так же: новое поле, новый экран, старый код
   выключается по факту.

Такой порядок снимает необходимость в слое атомарной записи поверх всего
профиля: у новой коллекции один писатель — сервер мини-аппа.

## 4. Активность в чате

Сейчас в чат пишут четыре файла: `alc_achievements.py`, `alc_expeditions.py`,
`alc_raids.py`, `alc_tasks.py` (события форта каждые 2 часа, рейды, утренний
отчёт в 3:10 по МСК). По решению владельца автоматические публикации остаются
только у старой игры; новая даёт кнопку «Поделиться в чат» — игрок сам решает,
что показать.

Технически это означает: сервер мини-аппа **не** отправляет сообщения в чаты
сам. Публикация — отдельное явное действие игрока, с проверкой, что он имеет
право писать в этот чат. Это проще и безопаснее, чем фоновые рассылки.

## 5. Что осталось открытым

1. **Доступ.** Владелец выбрал «только игроки одобренных групп», но
   `handlers/auth.py:12–38` пропускает все личные сообщения и ограничивает лишь
   группы; в `initData` приходит user ID, а не чат. Нужен выбор: проверять
   `getChatMember` по одобренным группам или считать «своим» того, кто есть в
   `alchemy_players`.
2. **Хостинг.** Бот на Render, значит HTTPS-адрес есть (`*.onrender.com`).
   Начать с одного origin (страница и API в процессе бота — CORS не нужен) или
   сразу разносить статику на бесплатный хостинг?
3. **Тестовый контур.** Отдельный тестовый бот и отдельная база — или проверка
   на копии рабочей?
4. **Старые команды.** Владелец ещё не решил, что с ними делать: это часть
   «развлекательного контента для активности в чате». Решение можно отложить,
   потому что на первом этапе они не трогаются.

## 6. Порядок работ

1. Новая коллекция прогресса лаборатории + API (`GET /api/profile`,
   `POST /api/craft`) поверх проверки `initData` (уже готова в
   `miniapp_backend/auth.py`).
2. Интерфейс: `miniapp_preview/` переключить с `offline_adapter.js` на API.
3. Кнопка «Поделиться в чат» — явное действие игрока.
4. Пилот на 2–3 игроках из одобренных групп.
5. По готовности — выключение старых команд лаборатории; их поля остаются
   архивом.
6. Второй аттракцион — тем же способом.

## 7. Ворота готовности первого этапа

- прогресс лаборатории сохраняется между заходами и устройствами;
- старая игра в боте работает без изменений (ни одна команда не сломана);
- повтор запроса крафта не списывает второй раз;
- посторонний без одобренной группы получает отказ;
- публикация в чат происходит только по действию игрока;
- при рестарте бота открытый мини-апп не ломается молча.

## 8. Что документ намеренно не обещает

- полный перенос алхимии за один этап;
- сохранение старых складов и уровней (решение: архив);
- работу без проверки `initData` и без ограничения доступа;
- фоновые рассылки в чаты из мини-аппа.

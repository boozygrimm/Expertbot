# Стратегия развития Mini App «Луна-парк» — вариант 1

**Дата:** 2026-11-21. **Статус:** стратегия, к исполнению не принята. Код не
меняется: этот документ только фиксирует решения, порядок и риски.

**Вводные, полученные от владельца** (эта сессия):

| Вопрос | Ответ |
|---|---|
| Аудитория первых месяцев | 10–30 человек |
| Первая версия | просмотр + настоящий крафт |
| Хостинг | статика отдельно, API в существующем процессе бота |

Всё ниже — следствия из этих трёх ответов. Где ответа нет, это помечено как
открытый вопрос, а не заполнено догадкой.

---

## 1. Короткий вывод

Ответ «просмотр + настоящий крафт» переносит центр тяжести проекта с интерфейса
на **сохранность инвентаря**. При 10–30 игроках нагрузка не проблема, а вот
потеря ресурсов и незаметное задвоение — проблема, и она возможна уже сегодня:

- `handlers/alc_lab.py:411–437` читает профиль целиком, списывает ингредиенты в
  памяти и пишет обратно **весь** `inventory` через `$set`. Условие в фильтре
  только `user_id`, версии документа и проверки остатка в самой записи нет.
- `handlers/alc_tasks.py:188–191` (ежечасное производство) делает то же самое с
  `inventory` и `production_slots`.
- Задание `process_expeditions_tick` идёт **каждую минуту**, спрашивая
  выносливость — оно не пишет инвентарь, но конкурирует за документ.
- Худший случай реалистичен: игрок жмёт «Смешать» в Mini App и в боте почти
  одновременно с ежечасным начислением производства. Более поздняя запись
  затрёт чужую, и одна из операций исчезнет молча.

Вывод: **первая версия не может писаться прямым `$set` всего инвентаря**. Нужен
один общий слой записи для бота и Mini App. Иначе первый же инцидент обнулит
доверие к Mini App у всех 10–30 игроков сразу.

## 2. Что это меняет в порядке работ

Прежний порядок (`ALCHEMY_MINI_APP_PLAN.md`, раздел 6) начинался с read-only MVP
и только потом переходил к записи. При выборе «сразу крафт» этап записи нельзя
отложить — он становится частью первой версии. Отсюда порядок:

1. **Слой записи (до интерфейса).** Одна функция изменения профиля, через
   которую проходят и бот, и Mini App: условная запись по версии документа,
   повтор при конфликте, идемпотентность по ключу операции.
2. **Перевод существующих писателей.** Не всех сразу: сначала `lab_mix`,
   `lab_repeat` (крафт) и производство (`alc_tasks`), затем остальные 10 файлов
   из `LUNAPARK_GAMEPLAY_MAP.md`. Пока хотя бы один писатель пишет `$set` всего
   инвентаря, гарантии нет.
3. **API.** `POST /api/craft` и `GET /api/profile` поверх слоя записи, с
   проверкой `initData` (готово в `miniapp_backend/auth.py`) и сессией.
4. **Интерфейс.** Переиспользовать `miniapp_preview/`, но крафт переключить с
   `offline_adapter.js` на API.
5. **Пилот.** 2–3 игрока, потом остальные.

## 3. Стоимость варианта «статика отдельно, API в боте»

Это самый дешёвый по ресурсам и самый сложный по безопасности вариант. Что он
требует:

- **HTTPS для обоих.** Mini App открывается только по HTTPS. Если страницы
  лежат на бесплатном хостинге, а API — на боте, то API тоже нужен HTTPS-адрес,
  иначе браузер заблокирует запросы как mixed content.
- **CORS.** Статике на чужом домене нужно разрешение на запросы к API. Не
  `*`, а конкретный источник, иначе любой сайт сможет дергать API.
- **Проверка `initData` на сервере.** Уже реализована; важно не принимать ID из
  тела запроса.
- **Сессии.** Сейчас `miniapp_backend/sessions.py` держит сессии в памяти
  процесса. При рестарте бота все открытые Mini App разлогинятся. Для 10–30
  человек это приемлемо, если экран говорит «закрой и открой заново», а не
  молча ломается.
- **Лимит запросов.** Нужен хотя бы простой, чтобы один клик-спам не забивал
  бота: крафт трогает документ и Mongo-запросы.

Чего этот вариант **не** требует: второго процесса, второго планировщика,
дополнительной RAM. Для 10–30 человек этого достаточно.

## 4. Что показываем игроку в первой версии

Минимум, который опирается на уже готовое:

| Экран | Источник | Действие |
|---|---|---|
| Парк | `design/bender_lunapark_concept.png` как ориентир | вход в лабораторию, закрытые павильоны-заглушки |
| Лаборатория: коллекция, котёл, рецепты, история | `miniapp_preview/` | крафт через API |
| Профиль | `GET /api/profile` | только чтение: склад, открытые элементы |

Лаборатория открытий (контракты, улики, мастерство, проект парка) уже
спроектирована и проверена на телефоне, но она **не тратит инвентарь**. Это
хорошая вторая волна: она даёт причину возвращаться, не увеличивая риск записи.

## 5. Риски и что с ними делать

| Риск | Вероятность | Что делаем |
|---|---|---|
| Затирание инвентаря при параллельной записи | **высокая** | слой записи с версией и повтором; перевести всех писателей этих полей |
| Двойное начисление при повторе запроса | высокая | ключ идемпотентности на операцию крафта |
| Потеря сессии при рестарте бота | средняя | явный экран «открой заново», не белый экран |
| Регрессия в боте | средняя | бот и Mini App идут через один слой; поведение команд не меняется |
| Непонятный интерфейс на телефоне | средняя | проверка на реальном телефоне, затем UX-наблюдение на 2–3 игроках |
| Расходы | низкая при 10–30 | бесплатных вариантов хватает; см. `FREE_CAPACITY_OPTIONS.md` |

## 6. Ворота: когда считаем первую версию готовой

- ни одной потери или задвоения при одновременных действиях бота и Mini App
  (проверяется тестом на двух параллельных операциях, а не на глаз);
- инвентарь после крафта в Mini App совпадает с тем, что видит бот;
- повтор одного и того же запроса не списывает второй раз;
- рестарт бота не ломает открытый Mini App молча;
- команды бота работают как раньше.

## 7. Открытые вопросы (без ответа двигаться нельзя)

1. **HTTPS-адрес.** Нужен конкретный: домен, бесплатный хостинг, туннель.
   Пока его нет, ни статика, ни API не заработают в Telegram.
2. **Доступ.** Только игроки одобренных групп (как сейчас в боте) или Mini App
   открыт в личке любому? От этого зависит allowlist.
3. **Что именно крафтим.** Полный `lab_mix` со списанием ингредиентов — или
   отдельный «исследовательский» крафт без списания (как в прототипе)? Второй
   вариант радикально снижает риск и может оказаться достаточным для первой
   версии.
4. **Порог «хватит».** Должна ли первая версия покрывать базу, производство и
   экспедиции, или достаточно лаборатории?

## 8. Моя рекомендация

Порядок «сразу крафт» принят, но я бы поставил между ним и интерфейсом один
шаг, который экономит недели: **сперва слой записи и перевод трёх писателей**
(`alc_lab` крафт, `alc_tasks` производство, `alc_expeditions` тик). Это
единственная часть проекта, где ошибка необратима для игрока. Её можно сделать
и проверить на изолированной копии базы, не выпуская ни одного экрана Mini App.

После этого первая версия собирается из уже готовых деталей: интерфейс есть,
`auth.py` есть, API — тонкая обёртка над слоем записи.

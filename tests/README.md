# Тесты ExpertBot

Запускайте команды из корня репозитория в отдельном виртуальном окружении:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-test.txt
python -m pytest -q
```

В Windows PowerShell активация: `.venv\Scripts\Activate.ps1`. Запуск
`python -m pytest -v` показывает имена тестов; отдельный модуль, например,
`python -m pytest -q tests/test_social_rp.py`.

Также можно выполнить `python -m unittest discover -s tests -v`, но этот режим
не собирает свободные pytest-функции и pytest-классы, не являющиеся
`unittest.TestCase`. Для полного набора используйте pytest. Для проверки покрытия
нужен дополнительно установленный `pytest-cov`, он не входит в зависимости:
`python -m pytest --cov=handlers/social_rp tests/test_social_rp.py`.

## Что проверяется

- Алхимия, экспедиции, рейды, квесты, экономика и настройки уведомлений.
- Social RP, профиль, склонение и ограничения частоты.
- Права, настройки панели, меню и выбор формата, включая истечение и очистку.
- Поиск, изображения, контекст фото, история и расшифровка голосовых/кружков.
- Очередь студии, клиент и воркер, TTS-фолбэки, отправка и восстановление
  при неоднозначных сбоях; также логика безопасного развёртывания.
- Некоторые интеграционные тесты запускают настоящий FFmpeg и локальный HTTP
  сервер и записывают временные файлы. Для них нужен `ffmpeg` с необходимыми
  кодеками (`libopus`, `libx264`, AAC); без FFmpeg отдельные тесты пропускаются.
  `mongomock-motor` из `requirements-test.txt` имитирует MongoDB.

Тесты не требуют реальных ключей, Telegram, AI-провайдеров или работающей
MongoDB. Они используют моки и тестовые данные; локальный успех не доказывает
работу конкретного Render, InstaBox, Telegram, квот или базы production.
Не используйте production-токен для тестов и не выводите секреты в журналы.

## При добавлении тестов

Держите тесты независимыми от порядка и реальных внешних сервисов. Новые
проверки маршрутизации должны учитывать авторизацию чата, флаги панели и
поведение при ошибках; интеграции, создающие файлы, — использовать временные
каталоги. Указывайте причины возможных `skip`, а не фиксированное число якобы
проходящих тестов в документации.

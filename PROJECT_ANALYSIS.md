# Анализ проекта ExpertBot

## Обзор

Telegram бот для игры "Алхимия" с системой экспедиций, рейдов, крафта и управления бойцами.

## Структура проекта

### Основные модули

- `handlers/alc_*.py` — игровая логика (экспедиции, рейды, крафт, бойцы)
- `handlers/social_rp.py` — социальное ролевое
- `ai_logic.py` — интеграция с AI API
- `database.py` — работа с MongoDB
- `config.py` — конфигурация

### Размеры модулей

- `alc_expeditions.py` — > 25000 токенов (слишком большой)
- `alc_raids.py` — большой
- `alc_base.py` — большой
- `alc_core.py` — большой

## Проблемы

### 1. Архитектурные

- **Большие модули** — некоторые файлы слишком большие (> 25000 токенов)
- **Глобальные переменные** — состояние в памяти, теряется при рестарте
- **Дублирование кода** — одинаковые функции в разных модулях
- **Циклические импорты** — потенциальная проблема (прямо сейчас нет)

### 2. Качество кода

- **Широкие исключения** — много `except Exception:` без конкретизации
- **Частое использование `.get()`** — 1552 occurrences, может быть неочевидно
- **Много глобальных переменных** — 92 occurrences

### 3. Тестирование

- **Покрытие тестами** — хорошее для критической логики
- **Отсутствие тестов** — для UI функций и callback handlers

## Плюсы

- ✅ Нет `TODO/FIXME/XXX/HACK` комментариев
- ✅ Нет пустых `pass` блоков
- ✅ Используются type hints
- ✅ Структура модульная
- ✅ Используются async/await для IO операций
- ✅ Хорошее покрытие тестами для критической логики

## Планы по улучшению

### Приоритет 1: Критические улучшения

#### 1.1 Разбить большие модули

**Проблема:** `alc_expeditions.py` > 25000 токенов

**Решение:**
```
handlers/alc_expeditions/
├── __init__.py
├── models.py          # модели данных (Expedition, Event)
├── logic.py           # бизнес-логика (process, finalize)
├── handlers.py        # callback handlers
├── utils.py           # утилитные функции
└── constants.py       # константы
```

**Выгода:** легче поддерживать, меньше конфликтов при мерджах

#### 1.2 Вынести глобальные переменные

**Проблема:** состояние в памяти теряется при рестарте

**Решение:**
- Использовать Redis для сессий
- Хранить черновики в БД
- Кэшировать редко меняющиеся данные

**Выгода:** персистентность, масштабируемость

#### 1.3 Устранить дублирование

**Проблема:** одинаковые функции в разных модулях

**Решение:**
- Создать `handlers/alc_common.py` для общих функций
- Вынести `get_element_name`, `get_element_emoji`, `shorten_button_text`
- Объединить похожие функции

**Выгода:** меньше кода, легче поддерживать

### Приоритет 2: Улучшение качества кода

#### 2.1 Конкретизировать исключения

**Проблема:** много `except Exception:`

**Решение:**
```python
# Вместо:
try:
    ...
except Exception:
    ...

# Использовать:
try:
    ...
except (TelegramBadRequest, ValueError) as e:
    ...
```

**Выгода:** легче отладка, меньше скрытых ошибок

#### 2.2 Уменьшить использование `.get()`

**Проблема:** 1552 occurrences, может быть неочевидно

**Решение:**
- Использовать `dict.get()` с явным дефолтом
- Создать типизированные модели данных
- Использовать pydantic для валидации

**Выгода:** более явный код, меньше ошибок

### Приоритет 3: Улучшение тестирования

#### 3.1 Добавить интеграционные тесты

**Проблема:** только unit тесты

**Решение:**
- Тесты для callback handlers
- Тесты для cron jobs
- Тесты для API интеграций

**Выгода:** уверенность в работе всей системы

#### 3.2 Добавить тесты для UI функций

**Проблема:** нет тестов для текстовых функций

**Решение:**
- Тесты для `render_*` функций
- Тесты для `build_*` функций
- Снапшот тесты для клавиатур

**Выгода:** защита от регрессий в UI

### Приоритет 4: Долгосрочные улучшения

#### 4.1 Внедрить DI (Dependency Injection)

**Проблема:** жёсткие зависимости

**Решение:**
- Использовать dependency injection
- Передавать зависимости через параметры
- Использовать контейнер зависимостей

**Выгода:** легче тестировать, более гибкая архитектура

#### 4.2 Добавить логирование

**Проблема:** недостаточное логирование

**Решение:**
- Структурированное логирование
- Логирование критических операций
- Метрики и мониторинг

**Выгода:** легче отладка, лучше observability

#### 4.3 Добавить документацию

**Проблема:** нет документации

**Решение:**
- Docstrings для функций
- README с инструкциями
- Архитектурная документация

**Выгода:** легче онбординг, легче понимание кода

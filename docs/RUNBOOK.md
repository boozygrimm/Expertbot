# Runbook

## Назначение

Этот документ нужен для быстрой диагностики и обслуживания бота в проде или на стенде.

Цель:

- быстро понять, что сломалось
- где смотреть логи
- какие подсистемы завязаны друг на друга
- какие безопасные проверки делать первыми

## Базовые симптомы

### Бот не отвечает вообще

Проверить по порядку:

1. процесс `python main.py` вообще запущен
2. валиден ли `TELEGRAM_TOKEN`
3. есть ли доступ до MongoDB по `MONGO_URI`
4. не упал ли старт на `db.setup()`, `ensure_default_lore()` или `init_personas()`
5. проходит ли healthcheck `GET /`

### Healthcheck жив, но Telegram молчит

Вероятные причины:

- проблемы с polling
- невалидный токен
- бан/ограничение Telegram API
- процесс висит на внешнем I/O

Что проверить:

1. логи старта
2. выполнялся ли `bot.delete_webhook(drop_pending_updates=True)`
3. есть ли ошибки `aiogram` / `TelegramBadRequest` / `Forbidden`

### Бот отвечает не во всех чатах

Проверять:

1. `auth_chats.status`
2. middleware `AuthMiddleware`
3. доступность фич через `FeatureAccessMiddleware`
4. не отключён ли модуль в панели чата

## Быстрые проверки

### Локально в репозитории

```powershell
git status --short
python -m compileall main.py handlers ai_logic.py
```

### Проверка healthcheck

Если бот поднят локально:

```powershell
curl http://localhost:7860/
```

Ожидается `200 OK`.

### Проверка переменных окружения

Обязательно должны быть заданы:

- `TELEGRAM_TOKEN`
- `MONGO_URI`

Обычно также нужны:

- `ADMIN_ID`
- хотя бы один из ключевых LLM provider keys

## Подсистемы и типичные поломки

### MongoDB

Симптомы:

- бот не стартует
- не пишется история сообщений
- не работают настройки, авторизация, игры, алхимия

Проверки:

1. `MONGO_URI`
2. сеть до MongoDB
3. права пользователя Mongo
4. создаются ли индексы в `db.setup()`

Критичные коллекции:

- `messages`
- `settings`
- `auth_chats`
- `alchemy_players`
- `alchemy_lore`

### LLM / AI Layer

Симптомы:

- Экс молчит
- сводки пустые
- voice/image/search выдают деградированный ответ

Проверки:

1. заданы ли `GEMINI_KEYS`, `GROQ_KEYS`, `OPENROUTER_KEYS`
2. есть ли ошибки сетевого доступа у внешних провайдеров
3. не сработал ли временный circuit breaker Gemini
4. не возвращают ли провайдеры `429` / `5xx`

Замечание:

`ai_logic.py` использует fallback-цепочки. Частичный отказ одного провайдера не всегда означает отказ всей функции.

### Image Generation

Симптомы:

- `/img` зависает
- картинка не приходит
- списание/лимит не совпадает с ожидаемым

Проверки:

1. доступен ли Pollinations endpoint
2. пишет ли Telegram ошибку отправки фото
3. есть ли доступ в `db.game_data` и `db.economy`
4. не застряли ли запросы на `generation_lock`

### Voice Recognition

Симптомы:

- голосовые не расшифровываются
- бот отвечает на голосовые не всегда

Проверки:

1. включён ли `auto_voice` в `settings`
2. скачивается ли файл из Telegram
3. работает ли транскрибация в `ai_logic.py`
4. установлен ли `ffmpeg`, если он нужен на текущем контуре

### Music

Симптомы:

- `/song` ничего не находит
- выдача трека ломается

Проверки:

1. установлен ли `yt-dlp`
2. доступен ли внешний источник
3. не упал ли поиск кандидатов
4. нет ли проблем с временными файлами и отправкой Telegram media

### Search

Симптомы:

- web search пустой
- поиск отвечает слишком общо

Проверки:

1. работает ли `DDGS`
2. есть ли сетевой доступ наружу
3. проходит ли summarization через LLM fallback

### Daily Reports

Симптомы:

- отчёты не приходят по расписанию

Проверки:

1. активна ли запись `settings.setting = daily_report`
2. корректно ли задано `time`
3. работает ли `check_cron_time`
4. не отключена ли фича `daily_reports`
5. есть ли сообщения в `messages`, из которых строить summary

### Alchemy

Симптомы:

- `/base` не открывается
- походы, экспедиции или рейды не работают
- не приходят утренние отчёты

Проверки:

1. читается ли профиль из `alchemy_players`
2. не сломан ли `get_or_create_player()`
3. существует ли стартовый lore в `alchemy_lore`
4. живы ли scheduler jobs из `alc_tasks.py`
5. не переполнен ли склад, если “ничего не падает”

## Что делать при инциденте

### Шаг 1. Зафиксировать симптом

Собрать:

- какая команда или действие не сработали
- в каком чате
- у всех или у одного пользователя
- есть ли проблема только в одном модуле

### Шаг 2. Проверить scope

Определить класс сбоя:

- глобальный сбой всего бота
- сбой только Telegram layer
- сбой только Mongo
- сбой только внешнего сервиса
- сбой только одной фичи

### Шаг 3. Проверить последние изменения

```powershell
git log --oneline -n 10
git status --short
```

Если проблема появилась после свежего деплоя, сначала смотреть последние коммиты, а не гадать.

### Шаг 4. Проверить логи по месту

Ищем по ключевым маркерам:

- `Ошибка`
- `Telegram`
- `Mongo`
- `Groq`
- `Gemini`
- `OpenRouter`
- `Vision`
- `Pollinations`

### Шаг 5. Делать только узкий фикс

Правило для этого проекта:

- не рефакторить в момент аварии
- не трогать порядок routers
- не менять одновременно persistence и prompts
- фикс должен быть минимальным и проверяемым

## Безопасные команды после правок

```powershell
python -m compileall main.py ai_logic.py handlers
git diff
```

Если правка только в документации, достаточно `git diff`.

## Чего не делать

- не делать массовый рефактор под инцидент
- не менять порядок `include_router(...)` без отдельной проверки
- не трогать `DEFAULT_PLAYER_TEMPLATE` без понимания миграции
- не убирать fallback-цепочки в `ai_logic.py` “для чистоты”
- не править сразу все игровые модули одним коммитом

## Эскалация

Если после базовой диагностики неясно, где проблема, сначала определить подсистему:

1. Telegram
2. MongoDB
3. AI provider
4. Music/Search/Image external service
5. Alchemy scheduler

Только после этого делать targeted patch.

# Команды и обращения ExpertBot

Справочник относится к текущему коду, а не подтверждает настройки конкретного
сервера. В группах доступ должен быть одобрен владельцем бота; доступность
функций зависит от `/panel`, прав Telegram, состояния MongoDB и провайдеров.
[README](README.md) описывает хранение истории, квоты и развёртывание.

Telegram-меню показывает только часть команд: его списки по ЛС, ЛС владельца и
группам находятся в [bot_commands.py](bot_commands.py). Команда может работать,
даже если её нет в меню. Telegram не принимает кириллицу в `setMyCommands`;
кириллические алиасы обрабатываются ботом как введённый текст, но интерфейс
клиента может не предлагать их как команды.

## Пользователям

| Команда или обращение | Назначение и условия |
| --- | --- |
| `/start`, `/help`, `/хелп`, `/хэлп`, `/справка`, `/экс помощь` | Краткая справка; `/help@имя_бота` также поддерживается. Для Штаба используется отдельная глубокая ссылка `/start alcbase`, которую выдаёт `/base` в группе. |
| `/support` | Связь с владельцем. |
| `Экс, вопрос`, `Эксперт, вопрос` | Диалог, поиск, погода, музыка, рисунки, игры и другие действия; запрос можно отправить текстом, голосовым или кружком. Для голосовых нужен модуль «Голосовые». |
| Ответ на сообщение самого бота | Текст, голосовое или кружок могут продолжить разговор без слова «Экс»; голосовое/кружок сначала распознаются. Ответ на чужое сообщение сам по себе не является обращением. |
| Фото с подписью `Экс, что на фото?` или ответ на фото с вопросом `Экс, ...` | Прямое распознавание фото. При ошибке бот сообщает, что не смог его рассмотреть, а не придумывает содержание. |
| `/bender вопрос`, `Экс, кружок вопрос` | Прямой запрос видеокружка в группе при включённых «Кружках Бендера» и настроенной студии. Текст запроса можно не указывать. |
| `/img запрос`, `/pic запрос`, `/рис запрос` | Генерация изображения. Две бесплатные успешные отправки в день на пользователя и чат, затем 250 игровых очков; день по МСК. Нужен модуль «Картинки» и доступный провайдер. |
| `/song название` | Поиск музыки и выбор трека. Нужен модуль «Музыка». |
| `/voice`, `/voice on`, `/voice off` | Статус и управление **публикацией** расшифровок. В группе статус доступен участникам, а переключение — администраторам и владельцу бота; в ЛС — пользователю. При `/voice off` модуль «Голосовые» продолжает фоновое распознавание и сохранение текста. Команда доступна при включённом модуле. |
| `/gossip [число]`, `/сплетни [число]`, `/вещай [число]`, `/выбор [число]` | Сводка по последним сообщениям чата: по умолчанию 50, диапазон 1–3000. Текстовые `сплетни`, `вещай`, `выбор` тоже поддерживаются. Один эксперт отвечает сразу; при нескольких показывается выбор. Сплетни независимы от панели «Отчёты (резерв)» и расписания суточного отчёта. |
| `/pole`, `/vis` (алиас `/виселица`) | Поле чудес и Виселица. |
| `/anachronism [ставка]`, `/анахронизм [ставка]`, `/ставка [ставка]` | Анахронизм; по умолчанию ставка 1000, необходимы очки в этом чате. |
| `/stop`, `/хватит` | Остановить активную партию Поля чудес или Виселицы. |
| `/topgame`, `/топигр`, `/очки` | Общий рейтинг игроков чата. |
| `/топполе [дни]` | Статистика Поля чудес, необязательный период в днях. |
| `/base`, `/база` | Штаб алхимии в ЛС; в группе бот выдаёт ссылку в ЛС. |
| `/pohod`, `/поход`, `/добыча` | Меню экспедиции алхимика. |
| `/грабить` | Рейд: нужен собранный и заряженный отряд. Ответом на игрока — нападение на него; без цели или при ответе боту — предложение PvE. |
| `Экс, шпора название` | Рецепт алхимии через Экса; после успешного запроса действует пятиминутная пауза. `/шпора` — отдельная команда только для владельца. |
| `/соцсправка`, `/ник имя`, `/пол м`, `/пол ж` | Справка Social RP и настройки профиля в чате. Само RP запускается текстом-ответом на другого участника, например `обнять`; модуль должен быть включён. |

Обычный ответ в группе может предлагать **⭕ Кружок / 🎙 Голос / 💬 Текст**
в зависимости от настроек панели. Выбирает автор запроса; выбор истекает через
3 минуты, затем бот пытается удалить меню. Если доступны только текстовые
ответы, меню не показывается. Включённый «Автоответ голосом» обходит выбор
для обычных обращений входящим голосовым, но не кружком. Специальные действия
(музыка, поиск, изображения, игры и т. д.) выполняются своим путём.

## Администраторам группы

| Команда | Назначение |
| --- | --- |
| `/panel`, `/панель` | Панель модулей непосредственно в группе; менять настройки могут администраторы группы или владелец бота. В личке владельца открывает общий пульт. |
| `/социал`, `/социал18` | Включить или выключить обычное / взрослое RP; права администратора группы проверяются обработчиком. |
| `/set_daily ЧЧ:ММ`, `/cron ЧЧ:ММ` | Задать ежедневный отчёт в группе по МСК. При выключенном модуле суточного отчёта используйте `/panel`: панель запрашивает время при включении. |
| `/stop_daily` | Отключить ежедневный отчёт группы. |
| `/vest` | Скрытый ручной отчёт за сутки для администратора группы; точное текстовое совпадение `/vest`. |

`/voice on/off` управляет общей настройкой публикации группы и требует прав
администратора или владельца бота. Отключение модуля «Голосовые» в панели
останавливает новые фоновые распознавания; уже запущенные могут завершиться.
Переключатель «Отчёты (резерв)» сохранён для совместимости со старыми
настройками и не управляет сплетнями. «Суточный отчёт» настраивается отдельно.
Обращение к Эксу с просьбой о сплетнях по-прежнему требует включённого «Эксперта»;
для голосового или кружка нужен также модуль «Голосовые».

## Владельцу бота и диагностике

Команды ниже не предназначены для обычных игроков. Если не указано иное,
обработчики проверяют `ADMIN_ID`; это не то же самое, что администратор группы.
Не передавайте секреты бота, ключи и содержимое `.env` в чат.

| Команда | Назначение / риск |
| --- | --- |
| `/panel` в личке | Пульт владельца: все действия доступны инлайн-кнопками, печатать команды не нужно. Экран «Справка → Все команды» показывает полный перечень резервных текстовых команд по разделам, чтобы их не приходилось искать в документации.  новости, настройки рисования и поиска, доступ и расписания групп, инструменты алхимии и проверки сервисов. С главной доступны быстрые входы в общую подборку, сценарии и выпуски. Каждый экран подписан путём вида «Пульт › Новости › Сценарии» и заканчивается кнопками «Обновить» и «Назад»/«Закрыть»; «Закрыть» удаляет экран, «Назад» возвращает на шаг выше без потери сохранённых данных. Открытие раздела или переход назад отменяет незаконченный текстовый ввод, чтобы следующее сообщение не попало в старую форму. Рисование и поиск переключаются для всех чатов. Статус показывает сохранённые данные, не проверяя работу сервисов в реальном времени. Опасные действия запрашивают подтверждение. Подробнее: [новостные черновики](news_prototype/OWNER_DRAFTS.md). |
| `/raid_test` | Только своя личка (отправитель совпадает с ID чата). Владелец получает кнопку **Web App**, остальные отправляют заявку на тест. После допуска тестер тоже получает кнопку без прав пульта. Управление: «Пульт → Рейд · тест → Тестеры»; заявки также приходят владельцу с «Разрешить»/«Отклонить». Повтор команды не создаёт повторную заявку. Выход из незаконченной формы отменяет ввод только у владельца/допущенного тестера. Без рабочей игровой базы, серверного прогресса, CloudStorage и наград парка; у каждого свой локальный профиль Telegram ID на устройстве. Команда показана в меню только владельца; тестер вводит её вручную. |
| `/news_prepare ССЫЛКА`, `/news_prepare_many ССЫЛКИ` | Только ЛС владельца: подготовить один сценарий или несколько по ссылкам; акцент задаётся следующей строкой. Расходует квоту Gemini. |
| `/news_discover` | Только ЛС владельца: найти новые публикации в настроенных источниках, без рендера. |
| `/news_pick`, `/news_drafts`, `/news_draft НОМЕР` | Только ЛС владельца: выбрать сюжет из найденного, список черновиков и карточка одного черновика. Карточка показывает стадию и, для `editor_failed`, безопасный код причины. |
| `/news_source НОМЕР`, `/news_edit`, `/news_nofocus`, `/news_noimage`, `/news_novideo` | Только ЛС владельца: прислать текст источника вместо недоступной статьи, изменить текст сценария, убрать увеличенные области кадра, картинку или видеофрагмент. Правки идут по версии сценария и не запускают рендер. |
| `/news_retry НОМЕР` | Только ЛС владельца: один ручной повтор подготовки сценария после ошибки редактора, по уже сохранённому источнику. Расходует квоту Gemini, не перечитывает статью и не запускает рендер. Причина ошибки видна в `/news_draft НОМЕР`. Код `refused` означает отказ фильтра безопасности Gemini на самом материале: повтор того же запроса даст тот же результат, поэтому нужен другой источник или кнопка «Прислать текст источника»; `empty_answer` — пустой ответ, повтор возможен, но не гарантирован. |
| `/news_approve НОМЕР ВЕРСИЯ`, `/news_trial`, `/news_trial_next`, `/news_trial_status` | Только ЛС владельца: подтвердить рендер конкретной версии, поставить следующий выпуск и проверить состояние постановки. Без подтверждения рендер не начинается. |
| `/news_program`, `/news_programs`, `/news_program_status`, `/news_program_approve` | Только ЛС владельца: собрать выпуск из готовых черновиков, список выпусков, состояние и подтверждение рендера выпуска. |
| `/news_daily_status`, `/news_collected` | Прежние команды состояния сбора и просмотра новостей, сохранены для совместимости. |
| `/news`, `/news_list`, `/news_ready`, `/news_digest`, `/news_digest_status` | Команды отдельного старого режима ручного приёма; доступны в панели «Новости → Настройки новостей → Ручные новости и старые дайджесты», только если этот режим уже включён. Он несовместим с режимом сценариев владельца; дополнительные включённые этапы могут автоматически обработать сохранённый материал. |
| `/chats` | Управление авторизацией чатов. |
| `/cron`, `/set_daily` в ЛС | Меню настройки суточных отчётов для групп. |
| `/image_probe` | Только ЛС владельца: реальные запросы к Cloudflare и OVHcloud; расходуются квоты, игровые попытки и очки не списываются. |
| `/search_image_probe [запрос]` | Только ЛС владельца: реальная проверка поиска с изображением, расходует квоту поиска. |
| `/regen_quests` | Принудительно перегенерировать квесты **всем игрокам**. |
| `/lore_help`, `/справкалор`; `/lore_edit`, `/lore_edit seed`, `/cancel_lore` | Справка и редактор наследия; `seed` обновляет стартовые наследия, `cancel_lore` отменяет ввод. Старая инициализация редактора удаляет запись `forge_legacy`; пульт предупреждает о ней до открытия редактора. |
| `/шпора [название]` | Точный рецепт; без названия полный список доступен только в ЛС владельца. |
| `/promo [s\|m\|l\|xl]`, `/промо [s\|m\|l\|xl]` | Выдать промо-пак алхимии игроку через reply; по умолчанию `s`. Изменяет инвентарь. |
| `/clear_inv` | Очистить инвентарь игрока через reply. **Необратимое изменение данных.** |
| `/alc_reset ID` | Удалить профиль алхимика по ID. **Необратимое изменение данных.** |
| `/промокод сумма` | Начислить или списать игровые очки через reply; также поддерживается поиск по имени. В этом старом обработчике ID владельца зашит отдельно, а не берётся из `ADMIN_ID`. Кнопочное изменение очков доступно владельцу из `ADMIN_ID`: выбирается группа и игрок из недавних записей или по ID, затем показывается подтверждение. |

При выдаче промопака, очистке инвентаря и удалении профиля через пульт можно выбрать игрока из 20 показанных или ввести числовой Telegram ID. Для промопака новому игроку дополнительно потребуется имя и подтверждение создания профиля. Профиль алхимии общий, не групповой. Для очков сначала выбирается конкретная группа, затем игрок из недавних записей или вводится его ID; новому игроку необходимо также указать имя. За одно действие допустимо начислить или списать до миллиона очков. Старые команды сохраняют свои прежние правила.

Дополнительный старый новостной режим не нужен для ежедневной подборки. Пульт не включает этот режим и его фоновые этапы. При добавлении материала и сборке дайджеста нужна отдельная проверка и подтверждение; в кнопочном выборе доступны до 100 последних готовых сюжетов, не более 20 на дайджест. При отключённом режиме этот раздел только показывает его состояние.

### Проверка Рейда в настоящем Telegram

После развёртывания этой версии **текущего бота** владелец отправляет `/raid_test`
в его личку (или `/panel` → «Рейд · тест»), затем нажимает **«Открыть Рейд · тест»**.
**Теперь вход ведёт в RAID · магитех**, `lunapark-raid-magitech.html?telegram=1`,
а ожидаемый build берётся именно из этой сборки. Классический `lunapark-raid.html`
остаётся отдельным контрольным пробником; его прогресс не переносится и не стирается.
После обновления процесса бота запроси **свежий `/raid_test`**: старые сообщения с
Web App-кнопкой сохраняют старый адрес. Деплой GitHub Pages обновляет страницу,
но сам по себе не перезапускает бота. По подтверждённой владельцем настройке Render
автоматически обновляет действующего бота из `main`; это отдельный rollout, а не
результат workflow Pages. Второй polling-экземпляр для теста не нужен и не запускается.
После выпуска дождись обеих публикаций, закрой старое окно игры, запроси свежий вход
и сверь сборку бота у кнопки с номером внутри Mini App. Если номера расходятся,
пока не рассылай объявление. Смена адреса не требует повторного допуска.
Для тестеров: человек сначала открывает личку бота и пишет `/raid_test`; владельцу
приходит заявка с ID и кнопками «Разрешить»/«Отклонить». После разрешения бот
присылает тестеру его кнопку запуска. Список и повторный допуск — **«Пульт →
Рейд · тест → Тестеры»**, вкладки «Заявки»/«Допущенные»/«Все». Удаление допуска
требует подтверждения и не стирает локальный прогресс. Отклонённые/отозванные
заявки повтором команды не рассылаются заново; владелец может разрешить их из «Все».
Тестеры не получают пульт или другие админские права. Если уведомление не доставлено,
заявка/решение остаются в списке; допущенный тестер может снова написать `/raid_test`.
Нужна именно Web App-кнопка: обычная ссылка Pages открывает браузер и не доказывает
запуск Mini App. Номер «Ожидаемая сборка» у кнопки сверяется с номером в самой игре.
Приватен вход из бота, **не** публичная статическая страница; проверки ID на клиенте
не заменяют серверную авторизацию, которая в этом пробнике не используется.
Отзыв запрещает выдачу **новых кнопок**, не блокирует старую кнопку/прямую ссылку
или уже открытую игру. В Mongo settings хранятся только metadata допуска и
уведомлений (ID, имя, статус, версия/время решения, отказ от обновлений, последний
итог отправки), не игровой прогресс.

**Окно «Что нового» внутри игры:** при первом входе в обновлённую сборку
показывает реальные изменения этого выпуска и короткую историю предыдущих этапов.
В этом выпуске каталог особых врагов завершён: **31 из31 уникальных типов
в четырёх стихиях =124 портрета**. Добавлен собственный Лич; общей временной
замены для особых типов больше нет. Прежние16 исходных портретов сохранены отдельно.
Новый арт виден и через «Продолжить» — новый забег/очистка данных не нужны.
Способности Лича, параметры врагов и боевые правила не меняются. Предыдущие10
образов, окно истории и защита от случайного закрытия описаны в краткой истории.

и автодеплоя существующего Render-бота закрой прежнее окно, запроси **свежий
`/raid_test`** и сверь build внутри игры. Старые сообщения с кнопками не меняются;
Pages SUCCESS само по себе не подтверждает версию процесса бота. Не запускай
второй экземпляр бота ради проверки и не очищай данные профиля.

«Понятно», Escape или Telegram «Назад» закрывают только эту справку и запоминают
сборку отдельно для своего магитех-профиля на устройстве. Новый рейд автоматически
не начинается; сохранённый не продолжается без отдельного «Продолжить», не
сбрасывается и не меняет обязательные награды/случайность. При следующем входе
в ту же сборку попап не повторяется. Снова прочитать — **«Что нового · история
обновлений»** на подготовке или в меню; **не очищай хранилище ради повторного
просмотра**. Во время цепочки/обязательной награды сначала заверши выбор.
Отметка прочтения — не активный сейв и не рекорд. Ошибка её записи показана,
окно всё равно можно закрыть, но при новом входе оно может появиться снова.
В SDK-режиме автоматический показ ждёт своего ID и не использует браузерную или
чужую отметку. Окно не отправляет сообщения или данные на сервер и не связано
с подпиской на Telegram-рассылку ниже. Для последующих выпусков текст «В этом
обновлении» поддерживается вместе с изменениями приложения.

**Объявления тестерам — после развёртывания этой версии бота:** только владельцу в
своей личке доступно **«Рейд · тест → 📣 Сообщить об обновлении»**. Пришли краткое
описание одним текстовым сообщением: до 700 UTF-16 единиц (эмодзи могут занимать две).
Сначала показываются **предпросмотр**, сборка из установленного HTML, кнопка проверки
игры и текущее число получателей; отправка — только отдельной кнопкой **«Отправить
тестерам»**. «Изменить описание» заменяет черновик; «Отмена», выход в тест/пульт и
`/raid_test` отменяют его. Старые «Отправить»/«Отмена»/«Изменить» другого или уже
закрытого черновика не отправляют рассылку и не отменяют новый ввод. Общие кнопки
навигации «Назад»/«Закрыть» выходят из текущей формы, как в остальных разделах.
Перезапуск бота теряет незавершённый черновик —
его нужно создать и подтвердить заново. Деплой и открытие меню сами ничего не рассылают.

Получатели — только допущенные тестеры, не отказавшиеся от обновлений. Список
проверяется при подтверждении, затем допуск/подписка — ещё раз перед каждым
сообщением; новые допуски во время отправки в начатую рассылку не добавляются.
В объявлении есть Web App-кнопка с ожидаемым build и **«🔕 Не присылать обновления»**.
В меню тестера есть **«Обновления: включены/выключены»** → отключение или повторное
включение. Это явные on/off действия только для собственного ID, не переключатель
из старого сообщения. Отказ сохраняется в settings после рестарта, не меняет допуск,
его revision или локальные сейвы и не сбрасывается повторным допуском. Решения по
заявке/отзыву приходят отдельно. Уже начатый сетевой запрос отозвать нельзя.

Итог владельцу: доставлено, доставка не подтверждена, пропущено, не завершено.
Перед первым Telegram-запросом сохраняется одноразовая отметка отправки; двойное
нажатие, старая кнопка и перезапуск не повторяют ту же отправку. При сбое проверки
допуска остаток останавливается. Таймаут не доказывает, что сообщение не дошло,
поэтому автоматических повторов/продолжения нет. После сбоя не повторяй объявление
всей аудитории вслепую: часть могла его получить. В settings остаётся только последняя
отметка/сводка, не база игровых событий. Разработка, тесты и merge настоящую рассылку
не запускают; подтверждение в личке остаётся за владельцем.

Сообщение входа отправляется **без защиты содержимого** (`protect_content=False`):
владельцу нужны скриншоты для теста, а доступ проверяется отдельно. Старый защищённый
вход не исправляется редактированием текста: после обновления процесса бота запроси
новый `/raid_test` или нажми «Обновить» под старым входом — бот пришлёт новое сообщение
без защиты и попытается удалить прежнее. Если удалить его не удалось, старую кнопку
не используй. Это снимает запрет **со стороны бота**, не настройки безопасности
самого клиента/телефона.

Оболочка вызывает ready/expand, отключает вертикальное сворачивание при поддержке
клиента (7.7+), учитывает стабильную высоту и безопасные отступы. Поле и подпись
занимают отдельные строки перед HP; если места мало, интерфейс прокручивается,
а не накладывается на шкалы. Во вложенных окнах «Назад» возвращает к игре, но не
отменяет обязательные награды. На основном экране остаётся **штатное закрытие Telegram**,
а не стрелка, зацикленная на меню. Нативное закрытие живого забега запрашивает
подтверждение при поддержке клиента.

**«Меню → Закрыть Mini App»** отменяет только незавершённый жест, записывает текущий
момент и вызывает SDK `close()`, не завершает забег и не выбирает награды. Если
сохранить не удалось, доступен явный выбор: остаться или всё равно закрыть с риском
потери последних действий. При отсутствии/ошибке метода закрытия показана подсказка
использовать кнопку Telegram. В обычном браузере **«Закрыть меню»** только скрывает
меню. Статус SDK/старого клиента/ошибки виден в пикере и меню; при сбое SDK локальная
игра остаётся временно доступной, но без определённого ID **не сохраняется** и не
подхватывает общие данные. Это **не** успешная проверка оболочки Telegram. Наш код
использует только числовой SDK ID для локального пространства ключей, не отправляет
initData и не запрашивает облако или рабочий игровой профиль.

**Прогресс раздельный:** забег, уровни/настройки классов, рекорды, достижения, режим/
сложность и трофейный счётчик относятся к своему Telegram ID на этом устройстве.
Даже при общем хранилище WebView другой аккаунт получает отдельный профиль. При
смене/пропаже ID запись прекращается; полностью закрой Mini App и открой заново.
Неизвестный/поздно загруженный ID не превращает уже начатую временную игру в чужой
сейв. Магитех использует только `raid:magitech:*` / `raid:magitech:tg:<ID>:*`:
ни браузерные `raid:*`, ни классические `raid:tg:<ID>:*` не импортируются даже
у владельца. Новые кнопки не содержат legacy-owner fragment. Уже существующий
**магитех-прогресс** того же ID сохраняется; классика остаётся в своём профиле.
Это разделение локальных данных, не серверная авторизация и не синхронизация
между телефонами/ПК; удаление данных WebView удалит сейв.

**Локация закреплена за забегом.** В меню показано только его текущее место.
В «Мехи и настройки» выбирается локация **нового** забега: предпросмотр не
перекрашивает текущую игру и не меняет её «Продолжить». Старт нового рейда
по-прежнему требует подтверждения замены. Сохранённая локация восстанавливается
независимо от последнего предпросмотра; старый магитех-save-v1 без поля локации
при первом продолжении использует прежнюю настройку оформления.
Справка и перезапуск остаются в меню; в компактной шапке — звук, свойства и меню.

**Стихийный бой включён только для новых забегов магитеха.** Существующее
«Продолжить» остаётся с прежним боем без сброса и перехода посреди рейда; на кнопке
и в меню указаны прежние правила. Для стихий нужен подтверждённый новый старт,
не очистка данных. Личные уровни мехов, настройки, достижения и рекорды сохраняются.
Новый сейв v2 хранит назначенные стихии и отдельную случайность; старые v1 читаются
и записываются по-старому. Классический пробник и его профили не меняются.

В новом рейде Огонь → Воздух → Земля → Вода → Огонь: вклад каждого меча/стрелы
×1,25 по следующей стихии, ×0,75 по предыдущей, ×1 по своей/противоположной.
База нейтральна, смешанные вклады складываются, округление/броня — один раз.
У босса две разные стихии, множитель — среднее двух; обе видны в подсказке и
деталях. Общий «Урон» цепи остаётся нейтральным, прогноз убийств учитывает цель.
Сок, отражение Острого, внешний Желе-Щит, яд/горение и навыки — по прежним правилам.

Пробные веса: оружие25% каждой; обычные враги местные; особые70% местные и по10%
остальных; boss местная+одна из3 других поровну. Это старт для теста, не финальный
баланс. Падение, перемешивание, Continue, меч→стрела/magic, просмотр магазина,
покупка и улучшение не перебрасывают существующие стихии. Цвет и готовый портрет
показывают боевое назначение, а не отдельную декоративную случайность.

Награды показываются компактно: все прибавки и потери видны сразу, полные параметры
вещей раскрываются отдельной кнопкой **«Подробнее»** без покупки/переброса. Заголовок
остаётся на месте, прокручивается содержимое. Числа урона/лечения врага появляются
на его клетке, героя — у HP; броня/опыт/золото/UP — у своих шкал, мана — у навыка.

На телефоне проверить: свежую магитех-кнопку и build, первое окно «Что нового»/
краткую историю и «Понятно» без автостарта/сброса, повторный вход без попапа и
его открытие вручную, подробности врага одним тапом без случайного закрытия;
затем верхнюю панель/HP без наложения, невозможность сменить локацию текущего
рейда через подготовку и перезапуск WebView → «Продолжить» в том же месте
с теми же стихиями и правилами;
старый забег должен остаться прежним, новый — включить стихийный бой. Проверить
смешанную цепочку/прогноз убийств, обе стихии босса в деталях, покупку/улучшение
без смены стихий; затем цепочку пальцем без сворачивания, меню и прокрутку наград/
достижений, «Подробнее»/возврат к выбору, числа у правильных получателей,
видимость «Подтвердить» в портретном и альбомном положении, «Назад»,
сворачивание и повторное открытие → **«Продолжить»**, неизменность выпавших карточек
и один ход врагов после завершения наград. Системная отмена незавершённого жеста
не должна делать ход. WebView может хранить сейвы отдельно от обычного браузера;
не очищать данные, ожидая переноса. Статическая публикация Pages и автотест SDK
**не подтверждают** обновление процесса бота или приёмку на физическом телефоне.

# ExpertBot

Telegram-бот на `aiogram` с несколькими режимами работы:

- чат-ассистент `Экс`
- генерация изображений
- поиск и сводки по чату
- музыка и расшифровка голосовых
- мини-игры
- крупный игровой модуль алхимии

Проект работает как long polling бот и одновременно поднимает HTTP healthcheck через `aiohttp`.

## Текущее состояние

Бот отвечает текстом, видеокружком или голосовым (в зависимости от настроек),
понимает обращения с фото и распознаёт речь из входящих голосовых и кружков.
`main.py` запускает бота и фоновые задачи, `app_setup.py` собирает диспетчер,
планировщик и healthcheck; `bot_commands.py` задаёт меню Telegram. Обработка
кружков и голосовых ответов использует отдельную студию на InstaBox.

Для групп требуется одобрение владельца, функции управляются через `/panel`.
Обычное обращение — текст с «Экс» или ответ на сообщение бота; подробности и
все команды, включая ограничения, перечислены в [COMMANDS.md](COMMANDS.md).
Данные переписки и результаты распознавания могут использоваться для сводок
и контекста; до включения функций уведомите участников чата.

## Отправка видео в группу от имени бота

Только владелец в личке: `/panel` → «Инструменты владельца» → «Отправить видео в чат».
Выберите одну из разрешённых групп, формат и пришлите видео, кружок или MP4-файл.
Доступ бота к группе проверяется перед подтверждением и перед отправкой. После
предпросмотра нужно отдельно подтвердить публикацию; отмена ничего не отправляет.
Обычное видео сохраняет текст подписи; кружок без подписи. Каналы и отдельные
темы форумов этим инструментом не выбираются.

Для превращения видео в кружок нужны `ffmpeg` (libx264, AAC) и `ffprobe` на
самом боте. Кружок — не более 60 секунд; исходный MP4 для преобразования —
до 20 000 000 байт (ограничение скачивания стандартного Bot API). Если файл
больше или длиннее, владелец сам обрезает его в Telegram; бот не обрезает время.
Кадр уменьшается целиком внутрь круглой области, свободное место заполняется
чёрными полями. Подготовленный кружок сначала отправляется владельцу в личку.
Обычное видео, полученное как видео Telegram, отправляется от имени бота по `file_id` без
скачивания и преобразования; для файла/кружка, переводимого в другой формат,
также действует предел 20 МБ. При неопределённом результате отправки бот не
повторяет её автоматически: сначала проверьте группу.

## Быстрый старт

### 1. Требования

- Python 3.12 для образа проекта (локальные тесты также запускались на 3.11)
- MongoDB
- `ffmpeg` и Node.js для музыкального модуля
- зависимости из `requirements.txt`

Docker-образ устанавливает `nodejs` и `ffmpeg`; для работы отдельной студии
нужны её собственные зависимости и `ffmpeg` с `libx264`, AAC и `libopus`.

Морфологию для Social RP (склонение ников и глаголов по полу) обеспечивает
`pymorphy3` — поддерживаемый форк `pymorphy2` с тем же API; словари
`pymorphy3-dicts-ru` ставятся вместе с ним. Менять на `pymorphy2` не нужно:
версия 0.9.1 не работает на Python 3.11+ (внутри вызывается удалённый
`inspect.getargspec`), из-за чего модуль `handlers/social_rp.py` не импортируется
и бот не стартует. Если морфология недоступна, Social RP автоматически
переключается на упрощённое склонение — это не ошибка, а запланированный fallback.

### 2. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```env
TELEGRAM_TOKEN=
MONGO_URI=
ADMIN_ID=
GEMINI_KEYS=
GROQ_KEYS=
GEMINI_GAME_KEY=
OPENROUTER_KEYS=
PORT=7860
```

Поддерживаются также альтернативные имена:

- `GEMINI_API_KEYS` вместо `GEMINI_KEYS`
- `GROQ_API_KEY` вместо `GROQ_KEYS`

### Поиск в интернете

Необязательная переменная `TAVILY_API_KEY` настраивает Tavily как основной
поиск и Firecrawl без ключа как резервный. У резерва есть дневной лимит на IP,
который может быть общим с другими приложениями. Резерв вызывается только
если основной сервис недоступен, не вернул результатов или ИИ счёл их
неподходящими; оценка ИИ может ошибаться. Если ИИ недоступен, показываются
непроверенные фрагменты с предупреждением, без расхода резервного лимита.
Tavily использует только `basic` без автонастроек. Чтобы избежать оплаты,
используйте бесплатные тарифы, не подключайте автопополнение и проверяйте
условия и лимиты в аккаунтах провайдеров. Сам код не контролирует биллинг.

Ответ выдаётся в характере Бендера без списка ссылок; фрагменты поиска
по-прежнему используются для ответа, а даты новостей передаются модели.

Картинки в обычном поиске по умолчанию выключены. После развёртывания
администратор может отправить боту в ЛС `/search_image_probe` или, например,
`/search_image_probe фото Марса`. Проба выполняет настоящий поиск с Render,
расходует квоту поиска и показывает текст и до одной иллюстрации, но не
расходует очки или попытки рисования. Картинка загружается Telegram по адресу
найденного файла; сторонний сайт может видеть запрос Telegram. Если отправка не
подтверждена, проверьте чат перед повтором.

После проверки включите картинки через `/panel` в личке владельца → «Картинки в
поиске». Настройка общая для всех чатов, хранится в Mongo и не требует
перезапуска Render. При поиске Tavily запросит описания изображений вместе с текстовыми результатами;
ИИ по описаниям выбирает подходящую иллюстрацию или отказывается от выбора. ИИ
может ошибаться, а картинка не подтверждает конкретное событие. При наличии
картинки ответ помещается в её подпись; если он длиннее лимита Telegram, остаток
отправляется отдельным сообщением. Если изображения нет, отбор не удался или
отправка фото не подтверждена, показывается текст. При потере подтверждения фото
его подпись и текст могут продублироваться; повторной отправки фото нет. При
переходе на Firecrawl результат пока только текстовый: поиск картинок резерва ещё не проверен. Для возврата к прежнему
поведению выключите картинки в том же разделе панели. Поиск с изображениями тратит квоту Tavily; дополнительный расход и
качество описаний нужно проверять по фактическому использованию аккаунта.

Если ключ не задан, сохраняется прежний поиск DDGS с резервом Википедии;
для новостей этот старый режим сообщает, что не может подтвердить дату. После настройки ключа используются только
Tavily и Firecrawl. Для новостей отбираются материалы с датой за последний месяц
(для «сегодня» — за последние 24 часа, для исторических запросов фильтра нет); это может
не найти свежие материалы, если источник не вернул дату. Доступность сервисов
и качество ответов нужно проверять на целевом сервере.

При первом открытии личной панели старые значения `SEARCH_IMAGES` и
`IMAGE_PROVIDER_MODE` сохраняются без изменения поведения. После успешного
открытия панели эти две переменные больше не нужны; сохранённые настройки имеют
приоритет. Ключи и адреса сервисов удалять не нужно.

### Генерация изображений

По умолчанию работает прежний Pollinations: добавление ключа само по себе не
переключает пользователей. Для поэтапного перехода задайте `CLOUDFLARE_ACCOUNT_ID`
и `CLOUDFLARE_AI_TOKEN` в окружении бота на Render; не публикуйте токен и не
отправляйте его в чат. Токен, сохранённый для проб на InstaBox, не доступен
процессу на Render автоматически. Изменения окружения вступают в силу после
перезапуска/развёртывания.

После развёртывания администратор `ADMIN_ID` может отправить **в личном чате с
ботом** `/image_probe`. Это проверит обе модели напрямую с сервера бота и
пришлёт отдельно подписанные результаты или ошибки. Команда не переключает
обычное рисование и не расходует пользовательские очки/попытки, но делает по
одному настоящему запросу к каждому сервису и тратит их квоты. Параллельные
запуски проверки в одном процессе блокируются. Проверка не заменяет тест обычной
команды `/img` после включения.

После проверки в `/panel` в личке владельца → «Рисование» выберите сервис.
При выборе Cloudflare основным станет Workers AI FLUX.2 Klein 4B (1024×1024),
резервом — OVHcloud SDXL. Для возврата выберите Pollinations в той же панели;
настройка общая для всех чатов и не требует перезапуска.
Для бесплатного Cloudflare нужен тариф **Workers Free**. Ранее объявлялась
суточная квота 10 000 Neurons на аккаунт с обновлением в 00:00 UTC; актуальные
лимиты, тариф и условия проверьте у провайдера. На платном тарифе возможны
списания: код не управляет биллингом.

В режиме `cloudflare` при ошибке сети, HTTP 401/408/429/5xx, некорректном
изображении или отсутствии настроек Cloudflare используется бесплатный анонимный
OVHcloud SDXL. При явно распознанном отказе по содержимому резерв не вызывается.
Также резерв разрешён для кодов недоступной модели или квоты 5007, 5028, 3036,
3040, в том числе при HTTP 400 или `success:false` с HTTP 200, если все коды
ответа относятся к этому списку. Неизвестные HTTP 400 и `success:false`, HTTP 403
и другие отказы запроса остаются без резерва, чтобы не обходить возможные
ограничения; 403 может также означать проблемы с доступом. Код 3030 сам по себе
не означает модерацию. При ошибке в журнал записываются только статус, числовые
коды и техническая категория, но не текст ответа провайдера, промпт или токен.
Если оба сервиса не ответили, изображение не отправляется и бот не записывает списание или расход
попытки. Автоматических повторов одного провайдера нет. Ранее для OVHcloud
указывался лимит двух анонимных запросов в минуту на IP и модель; актуальный
лимит нужно проверить у провайдера. Бот выдерживает 35 секунд между запросами
к резерву в рамках одного процесса, но другие процессы на том
же IP также используют этот лимит. Если лимит уже занят, запрос может не
пройти. Очередь, две бесплатные попытки и цена 250 очков сохранены. Лимит и
баланс проверяются, когда запрос достигает начала очереди, по текущей дате МСК;
в этом процессе проверка, отправка и учёт последовательны. Этот lock не является
межпроцессной блокировкой и не защищает от одновременного изменения баланса
другими функциями бота. Доставка и учёт выполняются по прежнему порядку —
сначала отправка, затем запись в БД. При неподтверждённом результате Telegram
или БД возможна неопределённость; перед повтором проверьте чат и состояние учёта.
В режиме `cloudflare` Pollinations не используется как резерв. Доступность и
качество каждого сервиса нужно проверить с сервера бота до переключения.

### Вопросы о фото

Пришлите фото с подписью `Экс, что на фото?` или ответьте на фото сообщением
`Экс, что на фото?`. Прямые запросы обрабатываются отдельно от фонового описания
из истории: если фото не удалось распознать, бот сообщает об этом, а не
выдумывает содержимое. Нужен включённый «Эксперт» и доступный vision-провайдер;
изображение передаётся внешнему сервису, поэтому не отправляйте чувствительные
данные без согласия. Распознавание может ошибаться. Обычный ответ может
предложить выбор формата; явный `Экс, кружок` или `/bender` запрашивает кружок.

### Голосовые, кружки и контекст диалога

В авторизованных чатах при включённом в панели модуле «Голосовые» бот в фоне
отправляет новые голосовые сообщения и звук кружков в Groq для расшифровки.
Текст сохраняется в истории `messages` (целевой TTL — 180 дней), не сам аудиофайл;
он может попасть в сплетни, сводки и контекст ответов. Уведомите участников чата.
Аудиофайлы и музыка не расшифровываются. История доступна только после успешной
расшифровки: большие файлы, ошибки, переполненная очередь и перезапуск могут
оставить сообщение без текста. Квоты и возможные расходы зависят от настроек Groq.
`/voice on` и `/voice off` управляют только публикацией текста в чат. В группе
переключать её могут администраторы и владелец бота, а посмотреть статус через
`/voice` — любой участник. В ЛС настройка доступна пользователю. Даже при
`/voice off` бот отвечает на голосовое или кружок, если распознанный текст начинается
с обращения «Экс» или запись отправлена прямым ответом на сообщение самого бота,
и модуль «Эксперт» включён. Для остановки распознавания и
сохранения новых записей выключите модуль «Голосовые» в панели. Уже отправленные
запросы могут завершиться после выключения модуля.

В обычном ответе Экса или кружке бот по возможности добавляет до пяти последних
сообщений за 15 минут, не смешивая темы форума. Неполная история и недоступная база
не блокируют ответ; распознавание и контекст могут ошибаться. Запрос к истории
ограничен по времени и не требует новых индексов.

#### Исходящие голосовые Бендера

В `/panel` настройка **«Голосовые ответы Бендера»** управляет голосовым в меню
выбора: пока её не меняли вручную, она следует настройке «Кружки Бендера».
Когда она включена, обычное обращение к Эксу предлагает голосовое и текст, а
если включены кружки — ещё и кружок. Автор запроса выбирает формат.
Независимая настройка **«Автоответ голосом»** по умолчанию выключена. При её
включении обычные обращения голосовым с «Экс» или в ответ на сообщение бота
идут в голосовой ответ без меню. Для обращений кружком остаётся выбор формата
(если в панели доступны кружки или голосовые ответы; иначе обычный текст).
Для автоответа также должны быть включены модули «Голосовые» и «Эксперт»;
`/voice off` не мешает ответу и не публикует расшифровку. Музыка, поиск,
картинки, игры и другие специальные действия выполняются как раньше.

Меню выбора действительно три минуты; после этого бот пытается удалить его из
чата. Очистка восстанавливается после перезапуска и повторяет попытки при ошибке
в течение суток. Если Telegram недоступен или сообщение нельзя удалить, меню
может остаться, но его кнопки уже не работают. Меню, созданные до обновления,
не имеют задания на автоматическую очистку.

Голос и кружок делят одну очередь студии на 10 заявок, включая текущую, поэтому
могут ждать друг друга. Используется тот же TTS, что и для кружка: при настройке
Gemini — Algenib, при его недоступности — локальный Tera. Воркер кодирует
голосовое в OGG/Opus без видеорендера. После подтверждённой отправки своего
голосового или кружка бот сохраняет в историю исходный текст для озвучки с
отметкой формата, без повторного распознавания и расхода Groq. Этот текст также
может использоваться при ответе на запись; фактическая речь может отличаться от
него. Сбой базы, перезапуск до сохранения или потеря ответа Telegram могут оставить
отправленную запись без истории; повторно медиа не отправляется. Записи подчиняются
общему сроку хранения истории.

Если озвучка или получение файла не удались, бот отправляет подготовленный текст;
при неизвестном результате отправки в чат предлагает сначала проверить чат и не
отправляет голосовое повторно. Переполненная очередь или сбой подготовки самого
текста обрабатываются отдельно.

Для работы голосового нужен обновлённый сервис студии на InstaBox **и** новый
код бота; старый воркер безопасно приводит к текстовому ответу. Никаких изменений
на серверах само добавление кода не делает. Перед обновлением дождитесь окончания
активной задачи и отдельно проверьте настройки, FFmpeg с `libopus`, права бота и
доставку обоих форматов. Подробнее: [video_prototype/README.md](video_prototype/README.md).

### Модели AI-провайдеров

Все идентификаторы моделей вынесены в [models.py](models.py) — это единая точка,
которую нужно править при очередной ротации моделей у провайдеров.

| Назначение | Переменная | Значение по умолчанию |
| --- | --- | --- |
| Быстрые запросы Groq (игры, нормализация, промпты для картинок) | `GROQ_FAST_MODELS` | `openai/gpt-oss-20b` |
| Основные запросы Groq (диалоги, отчёты, экспедиции) | `GROQ_STRONG_MODELS` | `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` |
| Служебный запрос для генерации картинок | `GROQ_IMAGE_PROMPT_MODEL` | `openai/gpt-oss-20b` |
| Расшифровка голосовых | `GROQ_TRANSCRIBE_MODELS` | `whisper-large-v3`, `whisper-large-v3-turbo` |
| Gemini (основной провайдер) | `GEMINI_CHAT_MODEL` | `gemini-3-flash-preview` |
| OpenRouter: текст | `OPENROUTER_TEXT_MODEL` | `google/gemma-3-27b-it:free` |
| OpenRouter: зрение | `OPENROUTER_VISION_MODEL` | `qwen/qwen3-vl-30b-thinking:free` |
| OpenRouter: сводки чата | `OPENROUTER_SUMMARY_MODEL` | `qwen/qwen-2.5-72b-instruct:free` |

Списки моделей задаются через запятую: порядок элементов = порядок фолбэка.
Если модель отвечает `400/404` (снята с публикации или недоступна на тарифе)
или ключ отвечает `401/403`, запрос автоматически уходит на следующую модель,
а не падает.

Доступность моделей, условия и тарифы провайдеров меняются независимо от кода.
Значения в таблице — именно **настройки по умолчанию в репозитории**, а не
подтверждение доступности для конкретного аккаунта. Проверьте лимиты и стоимость
в консоли соответствующего провайдера перед использованием. В быстром контуре
`gpt-oss` код задаёт `reasoning_effort=low`; запасной `qwen/qwen3.8-27b`
ранее описывался провайдером как preview.

#### Историческая миграция моделей Groq

При прежней миграции в коде были зафиксированы следующие даты отключения и
замены ([депрекации Groq](https://console.groq.com/docs/deprecations)). Это
историческая справка, а не проверка доступности моделей и тарифов сегодня:

| --- | --- | --- | --- |
| `llama-3.1-8b-instant` | 16.08.2026 | `openai/gpt-oss-20b` | `openai/gpt-oss-20b` (быстрый контур) |
| `llama-3.3-70b-versatile` | 16.08.2026 | `openai/gpt-oss-120b` | `openai/gpt-oss-120b` (основной контур) |

| `meta-llama/llama-4-scout-17b-16e-instruct` | 17.07.2026 | `openai/gpt-oss-120b` | `openai/gpt-oss-20b` (модель сидела в быстром контуре, там нужна скорость) |

Попутно учтены особенности новых моделей:

- вместо deprecated `max_tokens` отправляется `max_completion_tokens`;
- для `gpt-oss` передаётся `temperature=1` — другие значения модель отвергает;
- reasoning-модели (`gpt-oss`, `qwen3.x`) запрашиваются с `reasoning_format=hidden`
  и `reasoning_effort` (`low`/`medium` у gpt-oss, `none`/`low` у qwen), чтобы
  цепочка рассуждений не съедала лимит токенов и не обрезала ответ.

## База данных

Основные коллекции:

- `messages` — история сообщений чатов, целевой TTL 180 дней
- `settings` — настройки чатов и модулей
- `personas` — личности ассистента
- `auth_chats` — авторизация групп
- `game_data`, `economy`, `pole_history`, `pole_stats`
- `profiles` — Social RP
- `alchemy_players`, `alchemy_lore` — алхимия
- `ex_response_choices` — временный выбор формата и отдельные задания очистки меню
- `bender_video_queue` — общая очередь ответов студии

При запуске бот создаёт TTL-индекс `createdAt` на 180 дней либо увеличивает
существующий TTL через `collMod` без перестроения индекса. При нехватке прав
или неожиданной конфигурации индексов бот продолжит запуск, но прежний срок
может сохраниться: проверьте предупреждение `Message retention` в логах Render.
Другие TTL-индексы, если они есть, тоже могут удалять сообщения раньше. Уже
удалённые документы изменить срок хранения не вернёт. Более долгий срок увеличит
объём БД и время хранения содержимого переписки. Это относится только к
коллекции истории `messages`, а не к Telegram или другим коллекциям.

Подробности по архитектуре и данным: [PROJECT_ANALYSIS.md](PROJECT_ANALYSIS.md)

## Сплетни и отчёты

`/gossip 50`, `сплетни 50`, `/сплетни 50`, `/вещай` и `/выбор` запускают
сплетни по истории чата независимо от переключателя «Отчёты (резерв)» и
настройки суточного отчёта. Если эксперт один, он отвечает сразу; если их
несколько, появляется выбор. Группа должна быть авторизована. Запрос к Эксу
`Экс, сплетни` проходит через модуль «Эксперт», а голосовой или кружок также
требует включённого модуля «Голосовые».

Переключатель «Отчёты (резерв)» сохранён для совместимости и сейчас не управляет
сплетнями или суточным отчётом. Последний настраивается отдельно через
«Суточный отчёт» в панели. История чата и её хранение — отдельная функция.

## Фоновые задачи

Через `APScheduler` выполняются: проверка времени отчётов и тик экспедиций
раз в минуту, уведомления о прибытии раз в 2 минуты, проверка выносливости раз
в 10 минут, сбор производства раз в час, доход наследия в 03:00 МСК, upkeep и
утренний отчёт в 03:10 МСК, случайные нападения каждые 2 часа в 15 минут.
Источник расписания — `create_scheduler()` в [app_setup.py](app_setup.py).
Отдельные asyncio-задачи обрабатывают общую очередь студии, фоновую
транскрипцию и удаление просроченных меню выбора.

Фоновые уведомления игрок может отключить: в самом сообщении есть кнопка
«🔕 Не присылать отчёты» / «🔕 Не присылать отчёты о нападениях», а в главном
меню базы — независимые переключатели «📊 Отчёты» и «⚔️ Нападения». Отключение
глушит только сообщение: экономика (списание энергии, начисления наследия и
миров, потери добычи при налёте, пленные, счётчики) продолжает работать. Итоги
собственного рейда («☠️ ОТЧЁТ О РЕЙДЕ») приходят всегда — это отклик на действие
игрока, а не рассылка. Флаги, тексты кнопок и клавиатуры отчётов собраны в
`handlers/alc_notifications.py`.

## Тесты

Установите зависимости приложения и `requirements-test.txt`, затем запустите:

```bash
python -m pip install -r requirements.txt -r requirements-test.txt
python -m pytest -q
# Альтернативно: только unittest-тесты
python -m unittest discover -s tests -v
```

`pytest` дополнительно собирает тесты-функции, которые `unittest discover` не
запускает. Проверяются алхимия, права, маршрутизация, фото, поиск, аудио,
очередь и локальная связка студии. Часть тестов создаёт временные файлы,
использует локальный HTTP-сервер и FFmpeg; при отсутствии FFmpeg отдельные
проверки пропускаются. MongoDB, внешние AI API и Telegram в этих тестах
заменены имитациями: они не подтверждают живой production. Подробности —
[tests/README.md](tests/README.md).

## Важные ограничения проекта

- порядок подключения роутеров в `app_setup.py` важен; менять его нужно осознанно
- часть состояния игр хранится в памяти процесса и сбрасывается при рестарте
- `ai_logic.py` является крупным инфраструктурным модулем и содержит fallback-цепочки нескольких провайдеров
- автотесты уже есть, но покрытие всё ещё точечное, поэтому любые изменения лучше делать малыми патчами

## Telegram-команды

Команды для Telegram-меню задаются в [bot_commands.py](bot_commands.py).

- `USER_PRIVATE_COMMAND_SPECS` — обычные ЛС
- `ADMIN_PRIVATE_COMMAND_SPECS` — owner/admin ЛС scope
- `GROUP_COMMAND_SPECS` — группы

Порядок команд в меню определяется порядком элементов в этих списках.

Для `setMyCommands` Telegram принимает только `a-z`, `0-9`, `_`. Кириллические
алиасы обрабатываются ботом как текст, но не регистрируются в меню. Полный
список команд, прав доступа и известных ограничений — [COMMANDS.md](COMMANDS.md).

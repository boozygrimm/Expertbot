# ExpertBot

Telegram-бот на `aiogram` с несколькими режимами работы:

- чат-ассистент `Экс`
- генерация изображений
- поиск и сводки по чату
- музыка и расшифровка голосовых
- мини-игры
- крупный игровой модуль алхимии

Проект работает как long polling бот и одновременно поднимает HTTP healthcheck через `aiohttp`.

## Текущее состояние

Проект уже переведен на более аккуратную стартовую конфигурацию:

- `main.py` теперь в основном orchestrates startup
- `app_setup.py` собирает `Dispatcher`, scheduler и HTTP healthcheck
- `bot_commands.py` хранит Telegram-команды по scope и их порядок
- для чистой игровой и startup-логики добавлен лёгкий unit-test контур на `unittest`

Сейчас в проекте есть быстрые локальные тесты без реальной БД и без сетевых вызовов.

## Быстрый старт

### 1. Требования

- Python `3.12+`
- MongoDB
- `ffmpeg`
- зависимости из `requirements.txt`

Для музыкального модуля в Docker уже ставятся `nodejs` и `ffmpeg`.

Морфологию для Social RP (склонение ников и глаголов по полу) обеспечивает
`pymorphy3` — поддерживаемый форк `pymorphy2` с тем же API; словари
`pymorphy3-dicts-ru` ставятся вместе с ним. Менять на `pymorphy2` не нужно:
версия 0.9.1 не работает на Python 3.11+ (внутри вызывается удалённый
`inspect.getargspec`), из-за чего модуль `handlers/social_rp.py` не импортируется
и бот не стартует. Если морфология недоступна, Social RP автоматически
переключается на упрощённое склонение — это не ошибка, а запланированный fallback.

### Поиск в интернете

Необязательная переменная `TAVILY_API_KEY` настраивает Tavily как основной
поиск и Firecrawl без ключа как резервный. У резерва есть дневной лимит на IP,
который может быть общим с другими приложениями. Резерв вызывается только
если основной сервис недоступен, не вернул результатов или ИИ счёл их
неподходящими; оценка ИИ может ошибаться. Если ИИ недоступен, показываются
непроверенные фрагменты с предупреждением, без расхода резервного лимита.
Tavily использует только `basic` без автонастроек. Чтобы избежать оплаты,
используйте бесплатные тарифы, не подключайте автопополнение и проверяйте
условия и лимиты в аккаунтах провайдеров. Сам код не контролирует биллинг.

Ответ выдаётся в характере Бендера без списка ссылок; фрагменты поиска
по-прежнему используются для ответа, а даты новостей передаются модели.

Картинки в обычном поиске по умолчанию выключены. После развёртывания
администратор может отправить боту в ЛС `/search_image_probe` или, например,
`/search_image_probe фото Марса`. Проба выполняет настоящий поиск с Render,
расходует квоту поиска и показывает текст и до одной иллюстрации, но не
расходует очки или попытки рисования. Картинка загружается Telegram по адресу
найденного файла; сторонний сайт может видеть запрос Telegram. Если отправка не
подтверждена, проверьте чат перед повтором.

После проверки можно установить `SEARCH_IMAGES=enabled` и перезапустить Render.
При поиске Tavily запросит описания изображений вместе с текстовыми результатами;
ИИ по описаниям выбирает подходящую иллюстрацию или отказывается от выбора. ИИ
может ошибаться, а картинка не подтверждает конкретное событие. Сначала отправляется
текст, затем максимум одна картинка; если изображения нет, отбор не удался или
отправка не подтверждена, текст остаётся. При переходе на Firecrawl результат пока
только текстовый: поиск картинок резерва ещё не проверен. Для возврата к прежнему
поведению удалите `SEARCH_IMAGES` или задайте пустое значение и перезапустите
сервис. Поиск с изображениями тратит квоту Tavily; дополнительный расход и
качество описаний нужно проверять по фактическому использованию аккаунта.

Если ключ не задан, сохраняется прежний поиск DDGS с резервом Википедии;
для новостей этот старый режим сообщает, что не может подтвердить дату. После настройки ключа используются только
Tavily и Firecrawl. Для новостей отбираются материалы с датой за последний месяц
(для «сегодня» — за последние 24 часа, для исторических запросов фильтра нет); это может
не найти свежие материалы, если источник не вернул дату. Доступность сервисов
и качество ответов нужно проверять на целевом сервере.

### Генерация изображений

По умолчанию работает прежний Pollinations: добавление ключа само по себе не
переключает пользователей. Для поэтапного перехода задайте `CLOUDFLARE_ACCOUNT_ID`
и `CLOUDFLARE_AI_TOKEN` в окружении бота на Render; не публикуйте токен и не
отправляйте его в чат. Токен, сохранённый для проб на InstaBox, не доступен
процессу на Render автоматически. Изменения окружения вступают в силу после
перезапуска/развёртывания.

После развёртывания администратор `ADMIN_ID` может отправить **в личном чате с
ботом** `/image_probe`. Это проверит обе модели напрямую с сервера бота и
пришлёт отдельно подписанные результаты или ошибки. Команда не переключает
обычное рисование и не расходует пользовательские очки/попытки, но делает по
одному настоящему запросу к каждому сервису и тратит их квоты. Параллельные
запуски проверки в одном процессе блокируются. Проверка не заменяет тест обычной
команды `/img` после включения.

Только после успешной проверки добавьте `IMAGE_PROVIDER_MODE=cloudflare` в
окружение и примените настройки с перезапуском: основной станет Cloudflare
Workers AI FLUX.2 Klein 4B (1024×1024), резервом — OVHcloud SDXL. Чтобы вернуть
прежний режим, удалите переменную или установите `IMAGE_PROVIDER_MODE=legacy` и
перезапустите сервис. Неизвестное значение также оставляет прежний режим.
Для бесплатного Cloudflare нужен тариф **Workers Free**: суточная квота составляет
10 000 Neurons на аккаунт, обновляется в 00:00 UTC; на Workers Paid сверх квоты
возможны списания. Код не управляет тарифом.

В режиме `cloudflare` при ошибке сети, HTTP 401/408/429/5xx, некорректном
изображении или отсутствии настроек Cloudflare используется бесплатный анонимный
OVHcloud SDXL. При явно распознанном отказе по содержимому резерв не вызывается.
Также резерв разрешён для кодов недоступной модели или квоты 5007, 5028, 3036,
3040, в том числе при HTTP 400 или `success:false` с HTTP 200, если все коды
ответа относятся к этому списку. Неизвестные HTTP 400 и `success:false`, HTTP 403
и другие отказы запроса остаются без резерва, чтобы не обходить возможные
ограничения; 403 может также означать проблемы с доступом. Код 3030 сам по себе
не означает модерацию. При ошибке в журнал записываются только статус, числовые
коды и техническая категория, но не текст ответа провайдера, промпт или токен.
Если оба сервиса не ответили, изображение не отправляется и бот не записывает списание или расход
попытки. Автоматических повторов одного провайдера нет. OVHcloud ограничивает
анонимные запросы двумя в минуту на IP и модель: бот выдерживает 35 секунд
между запросами к резерву в рамках одного процесса, но другие процессы на том
же IP также используют этот лимит. Если лимит уже занят, запрос может не
пройти. Очередь, две бесплатные попытки и цена 250 очков сохранены. Лимит и
баланс проверяются, когда запрос достигает начала очереди, по текущей дате МСК;
в этом процессе проверка, отправка и учёт последовательны. Этот lock не является
межпроцессной блокировкой и не защищает от одновременного изменения баланса
другими функциями бота. Доставка и учёт выполняются по прежнему порядку —
сначала отправка, затем запись в БД. При неподтверждённом результате Telegram
или БД возможна неопределённость; перед повтором проверьте чат и состояние учёта.
В режиме `cloudflare` Pollinations не используется как резерв. Доступность и
качество каждого сервиса нужно проверить с сервера бота до переключения.

### Модели AI-провайдеров

Все идентификаторы моделей вынесены в [models.py](models.py) — это единая точка,
которую нужно править при очередной ротации моделей у провайдеров.

| Назначение | Переменная | Значение по умолчанию |
| --- | --- | --- |
| Быстрые запросы Groq (игры, нормализация, промпты для картинок) | `GROQ_FAST_MODELS` | `openai/gpt-oss-20b` |
| Основные запросы Groq (диалоги, отчёты, экспедиции) | `GROQ_STRONG_MODELS` | `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` |
| Служебный запрос для генерации картинок | `GROQ_IMAGE_PROMPT_MODEL` | `openai/gpt-oss-20b` |
| Расшифровка голосовых | `GROQ_TRANSCRIBE_MODELS` | `whisper-large-v3`, `whisper-large-v3-turbo` |
| Gemini (основной провайдер) | `GEMINI_CHAT_MODEL` | `gemini-3-flash-preview` |
| OpenRouter: текст | `OPENROUTER_TEXT_MODEL` | `google/gemma-3-27b-it:free` |
| OpenRouter: зрение | `OPENROUTER_VISION_MODEL` | `qwen/qwen3-vl-30b-thinking:free` |
| OpenRouter: сводки чата | `OPENROUTER_SUMMARY_MODEL` | `qwen/qwen-2.5-72b-instruct:free` |

Списки моделей задаются через запятую: порядок элементов = порядок фолбэка.
Если модель отвечает `400/404` (снята с публикации или недоступна на тарифе)
или ключ отвечает `401/403`, запрос автоматически уходит на следующую модель,
а не падает.

Особенности текущей линейки Groq:

- `openai/gpt-oss-120b` и `openai/gpt-oss-20b` — production-модели, стабильная замена
  снятым Llama;
- `qwen/qwen3.8-27b` — **preview**-модель: Groq может снять её с коротким уведомлением,
  поэтому она стоит в цепочке второй, после production-модели, и используется только
  как запасной вариант;
- базовые лимиты Groq для этих моделей — 30 RPM / 1 000 RPD / 8K TPM / 200K TPD
  (в доках таблица описывает базовые лимиты Developer-плана, точные значения своей
  организации видны в `console.groq.com/settings/limits`);
- reasoning-токены у `gpt-oss` тарифицируются как output и входят в TPM, поэтому
  в быстром контуре используется `reasoning_effort=low`, а не `medium`.

#### Миграция с устаревших моделей Groq (ноябрь 2026)

Groq вывел из free/developer-тарифов прежний парк моделей, запросы к этим ID
возвращают ошибку ([депрекации Groq](https://console.groq.com/docs/deprecations)):

| Было в коде | Отключено | Рекомендация Groq | В проекте заменено на |
| --- | --- | --- | --- |
| `llama-3.1-8b-instant` | 16.08.2026 | `openai/gpt-oss-20b` | `openai/gpt-oss-20b` (быстрый контур) |
| `llama-3.3-70b-versatile` | 16.08.2026 | `openai/gpt-oss-120b` | `openai/gpt-oss-120b` (основной контур) |
| `qwen/qwen3-32b` | 17.07.2026 | `openai/gpt-oss-120b` | `qwen/qwen3.8-27b` (запасной в основном контуре) |
| `meta-llama/llama-4-scout-17b-16e-instruct` | 17.07.2026 | `openai/gpt-oss-120b` | `openai/gpt-oss-20b` (модель сидела в быстром контуре, там нужна скорость) |

Попутно учтены особенности новых моделей:

- вместо deprecated `max_tokens` отправляется `max_completion_tokens`;
- для `gpt-oss` передаётся `temperature=1` — другие значения модель отвергает;
- reasoning-модели (`gpt-oss`, `qwen3.x`) запрашиваются с `reasoning_format=hidden`
  и `reasoning_effort` (`low`/`medium` у gpt-oss, `none`/`low` у qwen), чтобы
  цепочка рассуждений не съедала лимит токенов и не обрезала ответ.

### 3. Локальный запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

После старта бот:

- подключается к MongoDB
- поднимает индексы
- инициализирует личности
- регистрирует Telegram-команды
- запускает фоновые задачи
- открывает healthcheck на `GET /`

```powershell
docker build -t expertbot .
docker run --env-file .env -p 7860:7860 expertbot
```

## Структура проекта

```text
main.py               Точка входа и orchestration запуска
app_setup.py          Сборка dispatcher, scheduler и healthcheck-сервера
bot_commands.py       Команды Telegram по scope и их порядок
config.py             Чтение env и время по МСК
models.py             Реестр идентификаторов моделей всех AI-провайдеров
database.py           MongoDB client и коллекции
bot_instance.py       Singleton Bot
ai_logic.py           LLM/vision/audio utility layer и fallback-логика
personas.py           Базовые личности для Экса
handlers/             Telegram handlers и игровые модули
tests/                Быстрые unit-тесты на чистую логику
docs/                 Техническая документация
```

Ключевые группы модулей в `handlers/`:

- `ex_logic.py` — основной интеллект и маршрутизация запросов к Эксу
- `admin_panel.py`, `admin_cron.py`, `auth.py` — админка, доступ в чаты, расписания
- `reports.py`, `web_search.py`, `image_gen.py`, `music.py`, `voice_rec.py` — сервисные пользовательские функции
- `pole_chudes.py`, `viselitsa.py`, `anachronism.py`, `game_stats.py` — мини-игры
- `alc_*` — алхимический игровой контур
- `alc_notifications.py` — настройки фоновых уведомлений игрока: флаги отключения,
  тексты кнопок и клавиатуры отчётов. Модуль не импортирует другие хендлеры,
  поэтому его безопасно подключают меню базы, утренний отчёт и рейды

Основные коллекции:

- `messages` — история сообщений чатов, TTL 7 дней
- `settings` — настройки чатов и модулей

- `auth_chats` — авторизация групп

## Фоновые задачи

Через `APScheduler` выполняются:

- проверка времени ежедневных отчётов раз в минуту
- регенерация/тик алхимии
- доходы и upkeep
- утренний отчёт алхимии (3:10 МСК)
- тики экспедиций и рейдов, случайные налёты NPC-банд на форт

Точный список и расписание описаны в техдоке.

Фоновые уведомления игрок может отключить: в самом сообщении есть кнопка
«🔕 Не присылать отчёты» / «🔕 Не присылать отчёты о нападениях», а в главном
меню базы — независимые переключатели «📊 Отчёты» и «⚔️ Нападения». Отключение
глушит только сообщение: экономика (списание энергии, начисления наследия и
миров, потери добычи при налёте, пленные, счётчики) продолжает работать. Итоги
собственного рейда («☠️ ОТЧЁТ О РЕЙДЕ») приходят всегда — это отклик на действие
игрока, а не рассылка. Флаги, тексты кнопок и клавиатуры отчётов собраны в
`handlers/alc_notifications.py`.

## Тесты

Проект использует лёгкий тестовый контур на встроенном `unittest`.

Запуск:

```powershell
python -m unittest discover -s tests -v
```

Что сейчас уже покрыто:

- чистая логика алхимии и базовых расчётов
- бойцы, апгрейды и миграция старых данных
- статусы штаба, стройка, утренние отчёты
- расчёты экспедиций, рейдов и квестов
- startup-слой: команды, scheduler, healthcheck

Тесты специально держатся быстрыми:

- без записи файлов
- без реального MongoDB
- без сетевых вызовов
- без тяжёлых интеграционных прогонов

## Важные ограничения проекта

- порядок подключения роутеров в `main.py` важен
- порядок `include_router(...)` сохранён через `app_setup.py` и менять его нужно осознанно
- часть состояния игр хранится в памяти процесса и сбрасывается при рестарте
- `ai_logic.py` является крупным инфраструктурным модулем и содержит fallback-цепочки нескольких провайдеров
- автотесты уже есть, но покрытие всё ещё точечное, поэтому любые изменения лучше делать малыми патчами

## Telegram-команды

Команды для Telegram-меню задаются в [bot_commands.py](bot_commands.py).

- `USER_PRIVATE_COMMAND_SPECS` — обычные ЛС
- `ADMIN_PRIVATE_COMMAND_SPECS` — owner/admin ЛС scope
- `GROUP_COMMAND_SPECS` — группы

Порядок команд в меню определяется порядком элементов в этих списках.

Важно: для `setMyCommands` Telegram принимает только команды в формате `a-z`, `0-9`, `_`. Кириллические slash-команды можно поддерживать как текстовые aliases в хендлерах, но не как menu-команды.
